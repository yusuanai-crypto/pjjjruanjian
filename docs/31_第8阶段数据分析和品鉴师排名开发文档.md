## 2. 阶段目标

第 8 阶段目标是让老板、管理员和财务可以在 App 内按时间范围查看核心经营数据、品鉴师排名和打蛋率，并能从每个统计指标追溯到原始旅行团、订单和售后记录。

核心结果：

- 老板能自由选择开始日期和结束日期查看经营数据。
- 老板能使用本年、本月、上个月、近 10 天、昨日、今日六个预设。
- 数据看板展示出单销售额、退单销售额、总销售额、接待团数、接待人数、团均销售额、人均销售额、打蛋率。
- 品鉴师排名能按销售额、接待团数、接待人数、打蛋率排序。
- 品鉴师排名和明细能对上原始旅行团和订单。
- 打蛋率计算符合 PRD 定义。
- 全局标记过滤开启后，统计和排名只使用已标记客户和已标记旅行团相关数据。

## 3. 本阶段范围

### 3.1 本阶段要做

- 第 8 阶段 schema/索引差距清单。
- 统计日期预设和日期范围 helper。
- 经营看板 overview API。
- 品鉴师排名 API。
- 品鉴师排名详情和追溯明细 API。
- 趋势统计 API。
- 统计导出 API。
- 首页经营指标接入真实数据。
- Flutter 数据分析页面接入真实 API。
- 指标卡片、趋势图、排名列表、明细弹层或详情页。
- 角色权限、全局标记过滤、导出操作日志。
- 本地后端、Flutter 和云端 smoke 验收清单。

### 3.2 本阶段不做

- AI 自然语言问数和经营建议生成；这是第 9 阶段。
- 复杂 BI 报表、任意拖拽维度、多维数据仓库。
- 生产级数据缓存、离线 OLAP、跨年大数据分区。
- 自动修改经营数据；统计页面只读。
- 重新计算第 7 阶段提成和积分；第 8 阶段只读取已生成的源数据。
- 完整会计报表、工资报表、税务报表。

## 4. 当前基础和主要缺口

### 4.1 当前可复用基础

当前本地 schema 和代码已经提供：

- `travel_groups.visitDate`、`guestCount`、`tasterId`、`tasterName`、`groupType`、`financeMark`。
- `sales_orders.orderDate`、`travelGroupId`、`customerId`、`totalAmountCents`、`status`、`salesUserId`、`financeMark`。
- `after_sales_orders.refundAmountCents`、`financeConfirmed`、`salesOrderId`。
- `commission_records`、`travel_group_finance_summaries` 等第 7 阶段本地表。
- `customers.financeMark` 和 `travel_groups.financeMark`。
- `operation_logs`。
- 当前没有 analytics 相关 Prisma model/table，也没有 `analytics_daily_snapshots` 或 `taster_daily_snapshots`。
- 当前后端尚未创建 `analytics` module/controller/service，`AppModule` 也未挂载 AnalyticsModule。
- Flutter 端已有 `features/analytics/analytics_page.dart`，但当前主要是页面骨架和假数据。
- Flutter 端 `BusinessApi` 当前没有第 8 阶段 analytics 方法，数据分析页面尚未调用后端 API。
- Flutter 端已有 `MetricGrid`、日期筛选和部分排名 UI 组件思路，可复用。

### 4.2 当前主要缺口

- 后端尚未形成第 8 阶段统一 analytics API。
- 统计口径需要定版，尤其是出单销售额、退单销售额、总销售额、团均销售额、人均销售额的分母和日期范围。
- 品鉴师排名需要明确按旅行团到店日期统计，而不是简单按订单日期统计。
- 统计和排名必须复用全局标记过滤，不能另写一套松散 where 条件。
- 统计结果需要可追溯明细，目前页面假数据无法追溯到订单。
- 字段层面暂未发现必须补齐的缺口；索引层面需要对照 `docs/33_第8阶段数据分析和品鉴师排名Schema差距清单.md` 补充组合索引。
- 第 7 阶段云端未闭环，第 8 阶段云端 smoke 必须等待第 7 阶段接口部署和测试库确认。

## 5. 统计口径定版

### 5.1 日期范围和时区

- 日期统一按北京时间 `Asia/Shanghai`。
- `dateFrom`、`dateTo` 都是日期，查询时包含开始日和结束日。
- 后端接收 `YYYY-MM-DD`，返回标准化后的 `dateFrom`、`dateTo`。
- 如果未传日期，默认本月。

日期预设：

| 预设 | 口径 |
| --- | --- |
| `today` | 今天 |
| `yesterday` | 昨天 |
| `last_10_days` | 包含今天在内近 10 天 |
| `this_month` | 本月 1 日到今天 |
| `last_month` | 上个月 1 日到上个月最后一天 |
| `this_year` | 本年 1 月 1 日到今天 |
| `custom` | 用户手动选择 |

### 5.2 两类日期口径

第 8 阶段必须区分两个口径：

- 订单经营口径：销售额和退款金额默认按 `sales_orders.order_date` 统计。
- 接待/品鉴师口径：接待团数、接待人数、打蛋率、品鉴师排名默认按 `travel_groups.visit_date` 统计。

看板可以同时返回两个范围说明，避免老板看到销售额和接待团数时误以为它们来自同一个字段。

### 5.3 销售额指标

第 8 阶段默认使用已确认售后退款扣减，不使用订单状态推算退款金额。

```text
原始出单销售额 grossSalesAmountCents =
  范围内 sales_orders.total_amount_cents 合计
  订单状态包含 valid、partial_refund、refunded
  不包含 cancelled

已确认退单/退款金额 refundAmountCents =
  范围内 after_sales_orders.refund_amount_cents 合计
  finance_confirmed = true

总销售额 netSalesAmountCents =
  max(0, grossSalesAmountCents - refundAmountCents)
```

说明：

- `cancelled` 订单不进入原始出单销售额。
- `refunded` 订单如果曾经出单，可进入原始出单销售额，同时由已确认退款扣减；如果没有售后退款事实，应在 warnings 中提示 `refunded_order_without_confirmed_refund`。
- `partial_refund` 订单进入原始出单销售额，并由已确认退款扣减。
- 未确认售后退款不扣减总销售额，但可返回 `pendingRefundAmountCents` 作为风险提示。

### 5.4 接待指标

```text
totalGroupCount = 指定 visitDate 范围内旅行团数量
totalGuestCount = 指定 visitDate 范围内 travel_groups.guest_count 合计
groupScopedGrossSalesAmountCents = 指定 visitDate 范围内旅行团关联订单原始出单销售额
groupScopedRefundAmountCents = 这些订单的已确认退款金额
groupScopedNetSalesAmountCents = groupScopedGrossSalesAmountCents - groupScopedRefundAmountCents
averageSalesPerGroupCents = groupScopedNetSalesAmountCents / totalGroupCount
averageSalesPerGuestCents = groupScopedNetSalesAmountCents / totalGuestCount
```

分母为 0 时返回 0，不返回 null。

### 5.5 打蛋率

PRD 定义：

```text
打蛋率 = 没有产生有效订单的旅行团数量 / 总接待旅行团数量
```

第 8 阶段有效订单定义：

- 订单关联该旅行团。
- 订单状态为 `valid` 或 `partial_refund`。
- 订单有效金额大于 0。
- 订单有效金额 = `totalAmountCents - 已确认退款金额`。

因此：

```text
noEffectiveOrderGroupCount = 没有任何有效订单的旅行团数量
conversionGroupCount = totalGroupCount - noEffectiveOrderGroupCount
noOrderRate = noEffectiveOrderGroupCount / totalGroupCount
conversionRate = conversionGroupCount / totalGroupCount
```

页面显示名称使用业务已有叫法“打蛋率”，同时在详情中说明它表示“未产生有效订单的旅行团占比”。

### 5.6 品鉴师排名

品鉴师排名按旅行团接待口径统计：

- 主范围字段：`travel_groups.visit_date`。
- 主归属字段：`travel_groups.taster_id`，为空时归入“未分配品鉴师”并在 warnings 中提示。
- 销售额：该品鉴师在范围内接待旅行团关联订单的 `groupScopedNetSalesAmountCents`。
- 接待团数：该品鉴师接待的旅行团数量。
- 接待人数：这些旅行团的 `guestCount` 合计。
- 打蛋率：该品鉴师无有效订单旅行团数 / 该品鉴师接待团数。
- 团均销售额：该品鉴师净销售额 / 接待团数。
- 人均销售额：该品鉴师净销售额 / 接待人数。

排序支持：

- `netSalesAmountCents`
- `totalGroupCount`
- `totalGuestCount`
- `averageSalesPerGroupCents`
- `averageSalesPerGuestCents`
- `noOrderRate`

默认按 `netSalesAmountCents` 降序。

### 5.7 追溯要求

每个指标都必须能追溯到源数据：

- 销售额指标可追溯到订单列表和售后退款列表。
- 接待指标可追溯到旅行团列表。
- 品鉴师排名可追溯到该品鉴师的旅行团、订单、退款明细。
- 导出结果中的金额必须能与 API 明细对上。

## 6. Schema 和索引建议

第 8 阶段第一版建议优先实时聚合，不新增统计快照表。原因：

- 当前数据规模预计不大，实时聚合更透明。
- 统计口径还在第一版验证期，过早落快照容易固化错误口径。
- 每个指标都要求能追溯到原始订单，实时聚合更易核对。

`docs/33_第8阶段数据分析和品鉴师排名Schema差距清单.md` 已确认：

- 字段层面暂不需要新增字段。
- 当前没有 analytics 相关 model/table。
- 第一版可以不新增统计快照表。
- 已有单列索引基本覆盖源表追溯查询。
- 需要优先补齐面向统计聚合的组合索引。

### 6.1 已有可复用索引

当前已具备：

- 云端执行任何 migrate 前必须确认远端数据库是测试库，并确认第 7 阶段云端已闭环。
- 如本地压测发现实时聚合明显变慢，再设计 `analytics_daily_snapshots` 或 `taster_daily_snapshots`，不作为第一版主路径。

## 9. 全局标记过滤

当 `only_show_marked_records=true` 时：

- 订单统计必须只包含已标记客户，以及无旅行团或已标记旅行团关联订单。
- 旅行团统计必须只包含 `travel_groups.finance_mark=true` 的旅行团。
- 品鉴师排名必须基于过滤后的旅行团和订单。
- 售后退款只有在关联订单通过同一过滤作用域时才能进入统计。
- 导出与页面列表使用同一过滤 helper。
- 不允许前端本地过滤替代后端过滤。

实现建议：

- 订单作用域复用现有 `buildGlobalSalesOrderMarkScope` 规则：关联客户 `financeMark=true`，且 `travelGroupId=null` 或关联旅行团 `financeMark=true`。
- 旅行团作用域复用现有 `buildGlobalGroupMarkScope` 规则：`travel_groups.finance_mark=true`。
- 售后作用域不单独创建标记口径，通过 `salesOrder` 套订单作用域。
- 品鉴师排名先按旅行团作用域筛 `visitDate` 范围内的团，再汇总这些团的关联订单和售后。
- 如 helper 仍在单个 service 内，优先抽出公共 analytics scope helper。
- overview、ranking、detail、source、trend、export 必须使用同一套后端作用域；明细接口和导出不能绕开 overview/ranking 的过滤条件。
- `SalesOrder.financeMark` 已落库，但第 8 阶段默认不单独以订单自身标记作为统计过滤权威，除非后续业务文档明确调整口径。

## 14. 待确认但不阻塞本地设计的问题

以下问题如业务暂未确定，可按本文默认方案开发：

- 销售额看板日期口径：默认订单销售额按 `orderDate`，接待/排名按 `visitDate`。
- 团均和人均销售额：默认使用旅行团 visitDate 范围内的关联订单净销售额。
- 打蛋率中文展示：沿用业务叫法“打蛋率”，详情解释为“未产生有效订单的旅行团占比”。
- `refunded` 订单无确认退款事实：默认不扣减未确认金额，返回 warning。
- 是否统计导游自带团、待处理团：第 8 阶段第一版只统计正式 `travel_groups`；其他团表后续单独扩展。
- 是否新增统计快照表：默认不新增，先实时聚合；当前 schema 也没有 analytics 相关表，后续只在压测证明实时聚合变慢后再单独设计快照表。
- 是否修改 schema 字段：默认不新增字段；按 `docs/33_第8阶段数据分析和品鉴师排名Schema差距清单.md`，第一轮只建议补组合索引。
- 品鉴师为空的旅行团：默认归入“未分配品鉴师”，并返回 warning。
- 老板首页是否接入全部指标：默认只接入轻量今日摘要，完整统计在数据分析页。
