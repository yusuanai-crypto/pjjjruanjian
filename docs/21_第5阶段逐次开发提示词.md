# 第 5 阶段逐次开发提示词

本文根据 `docs/20_第5阶段二维码销售单和导出开发文档.md` 的开发顺序生成。每次开发建议只复制一条提示词给 Codex，完成、验证、提交或确认后，再进入下一条。

通用要求：

- 每次开始前先阅读 `docs/20_第5阶段二维码销售单和导出开发文档.md`。
- 同时参考 `docs/06_开发阶段计划.md`、`docs/05_数据库初步设计.md`、`docs/17_第4阶段客户和销售订单开发文档.md`、`docs/18_第4阶段逐次开发提示词.md` 和 `docs/19_第4阶段云服务器测试验收清单.md`。
- 只做当前提示词指定范围，不顺手做第 6 阶段完整售后、第 7 阶段提成积分、第 8 阶段统计或第 9 阶段 AI。
- 不覆盖生产数据，不连接生产库。
- 如涉及云服务器，必须先确认远端数据库是测试库；未确认前只做只读检查，不执行 migrate、seed 或写入 smoke。
- 如遇到现有未提交改动，先说明，不要擅自回滚用户改动。
- 每次完成后说明改了哪些文件、跑了哪些测试、还有哪些风险。

## 07. 开发生成二维码接口

```text
请开发 POST /api/sales-orders/:id/qr-code。

请求体：
- expiresInDays 可为空或 1 到 3650。
- regenerate 默认为 false。

要求：
1. admin 可为可见订单生成或重新生成二维码。
2. sales 只能为自己可见/负责的订单生成二维码。
3. finance、boss、after_sales 默认只读，不允许生成；如现有业务需要兼容，请说明原因。
4. regenerate=false 且已有未过期 token 时复用。
5. regenerate=true 时替换 token。
6. 写 qrCodeToken、qrCodeGeneratedAt、qrCodeExpiresAt。
7. 生成或重新生成都写 operation_logs，before/after 中不要记录过多客户隐私。
8. 返回 salesSheet 和 qrCode。

不要做：
- 不开发公开 HTML 页。
- 不改 Flutter。
- 不做 Excel 导出。

验证：
- 后端测试覆盖首次生成、复用、重新生成、非法有效期、销售越权、非授权角色失败、操作日志。
- cd server/api && npm test。
```

请开发 GET /api/public/sales-sheets/:token 公开扫码页。

验证：
