## 使用方法

1. 每次只复制一个代码块给 Codex。
2. 第一次从“01. 复核现有前端并生成 UI 差距清单”开始。
3. 完成、测试并人工确认当前步骤后，再执行下一条。
4. 本文只授权修改 Flutter 前端、Flutter 测试和前端设计文档；不授权修改后端、Prisma、migration 或生产数据。
5. 后端接口缺失或字段不一致时，记录为阻塞项并使用显式不可用状态，不得伪造数据或顺手修改后端。

## 前端通用要求

- 每次开始前完整阅读 `docs/44`、`docs/46`、`docs/47` 和本提示词；第 01 条完成后还要阅读 `docs/51_第11阶段仓库管理前端差距清单与UI设计.md`。
- 先执行 `git status`，保留并绕开已有未提交改动，不重置、不覆盖用户代码。
- 基于当前 `InventoryApi`、`BusinessApi`、DTO 和后端真实响应开发，不直接在 Widget 中拼接 URL，不重复创建第二套库存 API client。
- 优先复用项目现有的 `ResponsivePage`、`LoadingState`、`EmptyState`、`ErrorState`、`StatusTag`、确认弹窗、下载文件和错误映射组件。
- 不使用演示假数据、随机数据或仅本地内存模拟业务成功。后端能力未就绪时，页面必须显示明确的“功能暂不可用/等待接口”状态。
- 页面风格定位为内部经营管理工具：清晰、紧凑、稳重，强调数字可读性和操作效率，不追求装饰性动画。
- Windows/宽屏优先使用表格、筛选栏、详情侧栏或双栏工作台；手机端不得强行压缩宽表，改用卡片、分组详情和底部操作区。
- 所有数量统一显示“瓶”；数量输入只允许整数。金额由服务端整数分转换，按人民币格式展示。
- 采购单号、生产批次、批次序号、物流码始终按字符串处理，不能转数值，必须保留前导零。
- 库存状态不能只靠颜色表达，同时显示中文标签、图标或文字。正常、低库存、短缺、不可售、待补成本、待审批等状态样式必须统一。
- 列表必须具备加载、空数据、失败、重试、刷新、分页/加载更多和筛选无结果状态。
- 表单必须处理提交中禁用、防重复点击、后端校验错误、离开未保存提醒和成功后的局部刷新。
- 重要动作必须二次确认：入库生效、冲销、调出、调入确认、不可售转换、盘点提交、批准、驳回、出库确认、退货收货。
- 前端权限不能代替后端权限，但仍需做到最小请求：
  - `sales` 不显示仓库管理入口，也不请求任何库存数量或逐瓶可售列表。
  - `warehouse` 不请求、不缓存、不展示采购成本和库存金额。
  - `finance` 可查看数量和成本、维护批次成本，但不能出现直接调整库存数量的按钮。
  - `boss` 以只读为主，可查看库存成本并审批盘点。
  - `admin/super_admin` 拥有仓库配置和全部库存管理入口。
  - `after_sales` 只查看与售后单相关的退货处理进度，不进入全仓库存。
- 角色、token 或账号切换时必须清除库存与成本缓存，防止前一角色数据残留。
- 不在销售订单、公开二维码销售单、普通销售导出或 AI 助手中增加库存数量。
- 页面不可根据商品名称判断茅台，必须使用 `inventoryTrackingMode` 或后端能力字段。
- 每次完成后运行涉及范围的 `dart format`、`flutter analyze` 和 `flutter test`，报告改动文件、测试结果、接口阻塞和下一步建议。
- 不自动提交、推送、发布或部署，除非用户另行明确要求。

## 06. 完善调拨、在途和不可售库存界面

```text
请完善“调拨与在途”和“不可售库存”界面，不改后端。

调拨列表：
1. 按来源仓、目标仓、状态、商品、日期范围筛选。
2. 清晰显示待调出、在途、已收货、存在差异、已冲销等状态。
3. Windows 使用时间线/列表 + 右侧详情；手机使用卡片和步骤状态。
4. 详情显示调出、运输中、收货三个节点及操作者、时间、数量和差异备注。

新建调拨：
1. 来源仓与目标仓不能相同。
2. QUANTITY 商品填写正整数瓶数。
3. SERIALIZED 商品必须进入逐瓶选择流程并保留物流码字符串；后端未提供逐瓶调拨时显示阻塞，不退化为数量调拨。
4. 不显示销售角色入口，不向 warehouse 显示成本。

调出与收货：
1. 调出、收货分别二次确认并防重复点击。
2. 收货表单显示计划数量、实际收到数量和差异备注。
3. 部分收货、少收、损坏或后端冲突使用真实状态和错误；不在客户端直接改余额。
4. 调拨冲销必须填写原因，不提供删除。

不可售库存：
1. 按仓库、商品和原因筛选。
2. 标记不可售时填写数量和原因；恢复可售时也必须确认。
3. 清晰提示该操作只改变可售状态，不改变账面现存。
```
