# 开发阶段计划

本文把项目拆成多个阶段。这样做的目的，是让项目一步一步上线，而不是一次性做一个巨大系统。

总原则：

- 先把核心业务跑通。
- 先让真实员工用起来。
- 先保证数据准确。
- 再做统计、提成和 AI。

## 第 0 阶段：准备和确认

目标：

把需求、字段、权限、业务规则确认清楚。

要做的事：

- 确认员工角色和权限。
- 确认品鉴师只能查看自己接待的旅行团和自己的提成。
- 确认旅行团字段。
- 确认订单字段。
- 确认旅行团和客户标记信息规则。
- 确认老板和前台“只查询已标记信息”按钮的开启权限，以及管理员恢复权限。
- 确认二维码销售单展示样式。
- 确认售后流程。
- 收集提成和积分规则。
- 准备云服务器和苹果开发者账号。

交付物：

- PRD 文档
- 数据库初步设计
- 页面草图或字段表
- 第一版开发排期

为什么需要：

开发前如果字段和规则不清楚，后面会反复返工。这个阶段看似不写代码，但能节省大量时间。

## 第 1 阶段：基础框架和登录权限

目标：

让安卓、苹果、Windows 客户端能连接服务器，并完成登录。

要做的事：

- 创建 Flutter 客户端项目。
- 创建 NestJS 后端项目。
- 创建 PostgreSQL 数据库。
- 搭建用户表和角色权限。
- 加入品鉴师角色。
- 实现登录接口。
- 实现 App 登录页面。
- 实现不同角色看到不同菜单。
- 实现全局标记查询开关的后端基础能力。

验收标准：

- 员工可以登录。
- 管理员可以创建和停用账号。
- 不同角色登录后菜单不同。
- 品鉴师登录后只能看到自己的接待和提成入口。
- 登录失败有清晰提示。

为什么先做：

所有功能都依赖登录和权限。先把“谁能进系统、谁能看什么”做好，后面开发业务模块才安全。

## 第 2 阶段：前端 UI 设计

目标：

先把 App 的主要页面、操作路径和表单样式设计清楚，再进入业务功能开发。

要做的事：

- 设计安卓、苹果、Windows 共用的整体界面风格。
- 设计登录页、首页、角色菜单和权限入口。
- 设计前台、销售、品鉴师、财务、库管、售后、老板、管理员的首页布局。
- 设计旅行团录入表单、客户订单表单、二维码销售单页面。
- 设计财务查询页、库管打包页、售后开单页、数据分析页、AI 助手页。
- 设计列表、搜索、筛选、日期选择、状态标签、金额显示等通用组件。
- 确认手机端和 Windows 端的页面适配方式。
- 输出低保真页面草图或简单 UI 原型。

验收标准：

- 每个角色登录后应该看到哪些入口已经明确。
- 高频页面的字段顺序、按钮位置、查询条件已经明确。
- 手机端和 Windows 端的布局差异已经明确。
- 旅行团录入、销售开单、二维码销售单、财务查询、库管打包、售后开单、老板数据分析都有页面草图。
- 开发人员可以按 UI 设计直接进入页面开发，不需要临时决定页面结构。

为什么第二阶段做：

这个项目面向内部员工，录入效率比界面花哨更重要。先做 UI 设计，可以提前发现字段太多、按钮不好找、角色入口混乱等问题，减少后面返工。

## 第 3 阶段：旅行团管理

目标：

前台能正式录入旅行团，其他角色能按权限查询。

要做的事：

- 新增旅行团接口。
- 编辑旅行团接口。
- 旅行团列表和搜索。
- 旅行团详情页。
- App 端旅行团录入表单。
- 按日期、团号、旅行社、品鉴师、团型筛选。
- 旅行团增加标记信息，默认 0。
- 财务可以把旅行团标记信息改为 1。
- 品鉴师可以查看自己接待的旅行团。

验收标准：

- 前台能新增旅行团。
- 销售能查询旅行团并用于订单关联。
- 老板能查看旅行团列表。
- 品鉴师只能查看自己接待的旅行团。
- 财务能修改旅行团标记信息。
- 录入必填项为空时有提示。

为什么第三阶段做：

旅行团是销售订单和品鉴师统计的源头。先有团，后面订单才能正确关联。

## 第 4 阶段：客户和销售订单

目标：

销售能录入购买客人信息和订单。

要做的事：

- 客户表和订单表开发。
- 订单明细开发。
- 新增订单页面。
- 查询订单页面。
- 订单详情页面。
- 订单关联旅行团。
- 支持销售选择自带或邮寄，支持货到付款字段。
- 支持订单状态。
- 客户增加标记信息，默认 0。
- 财务可以把客户标记信息改为 1。

验收标准：

- 销售能新建订单。
- 订单能关联旅行团。
- 售后能通过姓名、电话、单号查订单。
- 财务能看到订单金额和物流费用。
- 财务能修改客户标记信息。
- 库管能看到待发货订单。

为什么第四阶段做：

订单是系统最核心的数据。订单跑通后，二维码销售单、售后、财务、提成、统计才有基础。

## 第 5 阶段：二维码销售单和导出

目标：

销售能快速生成二维码销售单，财务能导出数据核对。

要做的事：

- 设计二维码销售单展示模板。
- 订单详情页增加生成二维码入口。
- 手机支持扫码查看销售单详情。
- 客人可以拍照保存二维码和销售单信息。
- 订单列表支持 Excel 导出。
- 旅行团列表支持 Excel 导出。

验收标准：

- 销售可以从订单生成二维码销售单。
- 客人可以扫码查看或拍照保存。
- 财务可以导出订单 Excel。
- 导出的字段和页面显示一致。

为什么第五阶段做：

二维码销售单和导出是办公电子化的关键一步。销售不再打印销售单，改为让客人扫码和拍照留存，财务仍可导出 Excel 核对。

## 第 6 阶段：售后、财务、库管查询

目标：

售后、财务、库管能围绕订单完成日常工作。

要做的事：

- 售后单创建。
- 售后状态流转：协商中、待收货、待补发、待退款、已完成。
- 退款和退单记录。
- 财务查询页。
- 财务标记维护入口。
- 老板和前台“只查询已标记信息”按钮。
- 库管发货查询页。
- 库管选择物流方式、打包状态和打包件数。
- 财务填写物流单号、运费、是否开票。
- 重要修改记录操作日志。

验收标准：

- 售后能通过客户电话找到订单。
- 售后能创建并完成售后单。
- 售后状态只能从协商中、待收货、待补发、待退款、已完成中选择。
- 退单金额影响统计。
- 财务能查询退款和物流费用，并填写物流单号、运费、是否开票。
- 财务能把旅行团和客户标记信息从 0 改为 1。
- 老板或前台开启全局标记查询后，普通查询只显示标记信息为 1 的数据，只有管理员可以恢复。
- 库管能选择物流方式、打包状态和打包件数。

为什么第六阶段做：

这个阶段让多个部门都能使用系统，系统从“销售录单工具”变成“公司协作工具”。

## 第 7 阶段：提成和积分

目标：

根据订单计算旅行社积分和员工提成。

要做的事：

- 员工提成规则配置。
- 旅行社积分规则单独配置。
- 导入或维护旅行社扣酒成本规则。
- 导入或维护销售扣单成本规则。
- 销售提成计算。
- 品鉴师提成由财务手工输入。
- 外联提成计算。
- 销售组长提成计算。
- 财务旅行团返积分汇总页。
- 退单后重新计算或冲销。
- 提成明细导出。

验收标准：

- 管理员能维护规则。
- 新订单能生成销售、外联、组长提成记录。
- 旅行社积分能按旅行社上单金额、日返比例、月返比例计算。
- 财务能手工录入品鉴师提成。
- 财务能按旅行团查看总销售额、总扣酒成本、总上单金额、总日返金额、已返金额、未返金额和备注。
- 财务能查看每个人提成明细。
- 品鉴师能查看自己的提成明细。
- 退单后提成结果能正确调整。

为什么第七阶段做：

提成依赖订单、旅行团、售后数据。前面数据没跑通之前，提前做提成容易算错。

## 第 8 阶段：数据分析和品鉴师排名

目标：

老板能自由选择时间范围，也能快速使用常用预设查看经营数据。

要做的事：

- 数据看板。
- 品鉴师排名。
- 自由选择开始日期和结束日期。
- 预设本年、本月、上个月、近 10 天、昨日、今日。
- 出单销售额统计。
- 退单销售额统计。
- 总销售额统计。
- 总接待团数统计。
- 总接待人数统计。
- 团均销售额。
- 人均销售额。
- 打蛋率。

验收标准：

- 老板能自由选择开始日期和结束日期查看数据。
- 老板能使用本年、本月、上个月、近 10 天、昨日、今日六个预设。
- 品鉴师排名和明细能对上原始订单。
- 打蛋率计算符合文档定义。

为什么第八阶段做：

数据分析必须建立在稳定的真实数据上。先让员工录入，再让老板看统计，结果才可信。

## 第 9 阶段：AI 数据助手

目标：

老板、财务、售后能用自然语言快速查询和理解数据。

要做的事：

- AI 对话界面。
- 后端 AI 查询入口。
- 用户权限校验。
- 常见问题模板。
- 经营建议生成。
- AI 对话记录。
- AI 查询遵守老板全局标记查询开关。

验收标准：

- 老板能问销售额、排名、退单、打蛋率。
- 财务能问提成和退款。
- 售后能问客户订单。
- AI 不能查看用户无权限的数据。
- 老板或前台开启全局标记查询后，AI 只能使用标记信息为 1 的数据。
- AI 不能直接修改数据库。

为什么第九阶段做：

AI 的价值来自已有数据。如果前面业务数据不完整，AI 只能空谈。先把数据打牢，再接 AI 更稳。

## 第 10 阶段：上线、分发和运维

目标：

让员工稳定安装和使用，保证数据安全。

要做的事：

- 云服务器部署。
- 域名和 HTTPS。
- 数据库每日备份。
- 安卓 APK 内部分发。
- 苹果 TestFlight 内测。
- Windows 安装包分发。
- 管理员操作手册。
- 员工使用培训。
- 上线后问题收集。

验收标准：

- 安卓员工能安装并登录。
- 苹果手机员工能通过 TestFlight 安装并登录。
- Windows 电脑能安装并生成二维码销售单。
- 数据库每天自动备份。
- 出现问题能查看日志排查。

为什么上线阶段单独列出：

软件不是开发完就结束。安装、培训、备份、排错都决定它能不能真正长期使用。

## 推荐里程碑

### 里程碑 1：能登录、定 UI、录旅行团

包含：

- 登录
- 权限
- 前端 UI 原型
- 旅行团录入

业务价值：

先明确员工怎么操作 App，再让前台开始使用系统记录接待数据。

### 里程碑 2：能录订单和生成二维码

包含：

- 客户
- 订单
- 二维码销售单
- Excel 导出

业务价值：

销售和财务开始使用系统替代手工记录。

### 里程碑 3：能售后和发货

包含：

- 售后单
- 财务查询
- 库管查询
- 发货状态

业务价值：

多个部门围绕同一套数据协作。

### 里程碑 4：能算提成和看排名

包含：

- 提成规则
- 提成记录
- 品鉴师排名
- 经营看板

业务价值：

老板和财务可以减少人工统计。

### 里程碑 5：能 AI 查询

包含：

- AI 对话
- 权限内查数
- 经营建议

业务价值：

老板、财务、售后可以更快找到需要的信息。

## 开发注意事项

- 每完成一个阶段都要让真实员工试用。
- 表单字段不要一次堆太多，优先保证高频字段好填。
- 每个金额字段都要明确单位。
- 每个统计指标都要能追溯到原始订单。
- 所有关键修改都要记录日志。
- 先保证稳定和准确，再追求界面漂亮。
