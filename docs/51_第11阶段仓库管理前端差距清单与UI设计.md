# 第 11 阶段仓库管理前端差距清单与 UI 设计

更新日期：2026-08-01

## 0. 独立仓库管理页面落地状态

已新增 `WarehouseDirectoryPage`：

- 一级入口分为“库存管理”(`warehouse_management`) 与“仓库管理”(`warehouse_directory`)；库存可读角色可见，销售不可见且页面保护分支不创建库存 API。
- 桌面为左侧两级仓库树、右侧仓库资料与商品宽表；手机先显示仓库卡片，点击后进入详情与商品卡片，不压缩桌面宽表。
- 管理员/超级管理员可新建父仓、子仓、编辑、启停、设默认和受限删除；其他库存可读角色只读。
- 商品表明确区分本仓现存/占用/不可售/实际可售和父仓“含子仓汇总”，并提供盘点/调整、流水、逐瓶库存和安全移除操作。
- 逐瓶商品数量读取服务端真实逐瓶聚合结果；页面不创建物流码，也不允许用汇总初始数量替代逐瓶入库。
- “盘点/调整”通过一次性导航交接把 `warehouseId + productId` 传给既有 `stocktake` 模块；流水与逐瓶操作也进入既有页面，不新建第二套作业状态。
- 添加普通商品支持期初数量、二次确认、提交锁、失败保留输入和幂等键；逐瓶商品强制零库存添加并跳转原逐瓶页面。
- 原库存工作台的可写 `warehouse_settings` 模块已移除，仅保留原文件用于兼容测试和过渡，不再出现在导航中。

仍需人工联调的环境项：负责人目前沿用既有 `managerUserId` 契约，页面输入负责人账号 ID；待后端提供专用负责人 options 接口后可替换为姓名选择器。非零期初数量继续受现有库存维护期开账规则约束，生产启用后应引导使用盘点/调整，而不是重新开账。

1. 入库、调拨、盘点、预警、流水和报表的 P0 DTO/命令错位已完成当前接口范围修正；剩余差距主要是服务端查询投影和逐瓶盘点扫描器。
2. 售后实收已使用真实 receipt header + lines，严格区分 DRAFT 与 POST；旧“库管确认”不再冒充返库存，财务退款仍留在财务流程。
3. 销售出库与配货已嵌入现有唯一打包工作台；顾客退货已建立唯一实际收货工作台，并在售后页只读展示当前售后单的真实收货进度。
4. 各业务域已拆文件，列表/详情请求代次、身份隔离、统一失效和局部刷新已完成本轮治理；剩余工程风险主要是共享 options 重复加载，以及打包/逐瓶等旧页面仍需继续拆 controller。
5. 当前明确的后端查询阻塞包括“活动预警实例列表”和“无需分页遍历的库存数量总览聚合”；其他多数差距是前端尚未接入已有后端能力，不应笼统标成后端未实现。

### 1.3.1 状态大小写规范

后端库存 query 多数把入库、调拨、流水等枚举投影为小写；部分盘点状态仍为大写。当前前端 label 和按钮条件大量直接比较大写字符串。后续 adapter 必须在 DTO 边界统一成受控 enum，不能让 Widget 自行比较原始字符串。

建议：

- transport 层保留原始值用于诊断；
- domain DTO 统一使用 enum，如 `InventoryDocumentStatus.posted`；
- 中文标签、图标、`StatusTone` 由统一 formatter 输出；
- 未知状态显示“未知状态（原值）”，禁止只显示颜色或静默按默认状态处理。

### 1.3.2 标识符与金额

- 采购单号、生产批次、批次序号、物流码、调拨单号、入库单号均使用 `String`，不调用 `int.parse`，保留前导零。
- 数量统一用 `int`，UI 统一显示“瓶”；逐瓶模式的总数来自单元数量，不允许小数。
- 金额只接收服务端整数分。输入人民币金额时使用严格的十进制字符串转分函数，最多两位小数；当前 `(double * 100).round()` 应替换，避免浮点误差和三位小数被静默四舍五入。

## 4. 建议的仓库管理二级导航与页面设计

## 4.1 二级导航结构

建议保留 `warehouse_management` 作为唯一一级入口，在内部按业务分组：

```text
总览

基础设置
├─ 仓库设置
└─ 预警规则

库存作业
├─ 商品库存
├─ 入库与批次成本
├─ 调拨与在途
├─ 不可售库存
└─ 逐瓶库存

履约作业
├─ 销售出库与配货
└─ 顾客退货收货

盘点
├─ 商品盘点
└─ 盘点审批

查询分析
├─ 库存流水
├─ 活动预警
└─ 库存报表
```

按角色过滤后二级导航，不能先显示再在页面内部报无权。

## 4.2 每个页面的区域、筛选、列、详情和按钮

### 4.2.1 库存总览

- 主要区域：
  - 仓库切换器；
  - 真实指标卡；
  - 待处理事项；
  - 最近库存动态；
  - 快捷动作。
- 筛选：仓库、时间范围；boss/admin 可切“全部仓库”。
- 指标：
  - 可售、不可售、占用、在途均以“瓶”显示；
  - 短缺商品数、低库存商品数、待审批盘点数、待补成本批次数；
  - finance/admin/boss 可看库存金额；warehouse 不请求金额。
- 快捷动作：
  - warehouse/admin：新增入库、创建调拨、创建盘点、进入配货；
  - finance：admin/finance 进入待补成本；
  - boss：进入盘点审批；
  - 无权限动作不显示。
- 后端约束：没有可靠聚合来源的指标显示“功能暂不可用/等待汇总接口”，不得从第一页数据估算。

### 4.2.2 仓库设置

- 主要区域：仓库列表、详情/编辑侧栏、库存配置卡。
- 筛选：名称/编码、启用状态、是否默认。
- 列：编码、名称、负责人、地址、默认仓、启用状态、更新时间。
- 详情：字符串 ID、编码、名称、地址、负责人、默认/启用、版本、更新时间。
- 按钮：admin/super_admin 可新增、编辑、设默认、启用/停用；其他角色只读或不显示页面。
- 状态：
  - 停用前二次确认；
  - 后端因库存/在途/未完成单据/盘点拒绝时显示明确冲突原因；
  - 不能用本地开关模拟成功。

### 4.2.3 商品库存

- 主要区域：统计条、筛选栏、库存表/卡、详情侧栏。
- 筛选：
  - 仓库、商品、`inventoryTrackingMode`；
  - 正常、低库存、短缺、不可售、待补成本；
  - 仅有库存、仅在途；
  - 重置筛选。
- Windows 列：
  - 仓库、商品、跟踪模式；
  - 在手、占用、不可售、可售、在途、短缺；
  - 最低库存、状态、最近更新时间；
  - 成本覆盖、库存金额仅对有权限角色。
- 手机卡片：商品/仓库、可售、在手、占用、不可售、在途、文字状态。
- 详情：
  - 完整数值、计算公式和状态说明；
  - quantity 商品显示批次；
  - serialized 商品显示状态汇总，并链接逐瓶详情；
  - 成本区按角色完全裁剪。
- 按钮：刷新、打开批次、打开逐瓶详情；不提供“直接改数量”万能按钮。

### 4.2.4 入库与批次成本

- 主要区域：入库单列表、详情时间线、创建/冲销、待补成本工作区。
- 筛选：
  - 仓库、入库类型、状态、商品；
  - 采购单号、供应商、生产批次；
  - 业务日期范围、待补成本；
  - 所有编号按字符串查找。
- Windows 列：入库单号、类型、仓库、业务时间、商品摘要、数量、状态、操作人、成本状态。
- 详情：
  - 单号、来源、sourceKey、过账/冲销信息、附件元数据；
  - 每行商品、条件、数量；
  - 批次 ID、供应商、采购单号、生产批次、生产日期、剩余量、不可售量；
  - 有权限时显示单位成本和金额。
- 按钮：
  - warehouse/admin：新建并确认入库、冲销；
  - finance/admin：维护批次成本；
  - boss：只读；
  - 冲销和入库生效均二次确认。
- 表单：
  - 支持多行；
  - 商品用真实 option；
  - 数量正整数；
  - 采购单号/生产批次保留前导零；
  - 金额严格字符串转整数分；
  - 提交中禁用、后端字段错误定位、未保存离开提醒。

### 4.2.5 调拨与在途

- 主要区域：调拨列表、调拨详情/进度、分次收货工作台。
- 筛选：调出仓、调入仓、状态、商品、调拨单号、创建/调出日期、仅在途。
- Windows 列：调拨单号、调出仓、调入仓、商品/行数、计划、已调出、已收、差异、剩余在途、状态、更新时间。
- 详情：
  - from/to warehouse ID 和名称；
  - 每行真实 transferLineId、sourceLineKey、跟踪模式；
  - 计划、调出、已收、不可售、差异、剩余在途；
  - 逐瓶单元数/允许角色可见的单元 ID；
  - 调出单据、每次收货单、冲销链。
- 按钮：
  - warehouse/admin：创建、确认调出、确认调入、收货冲销、调出冲销；
  - 重要动作全部二次确认；
  - finance/boss 只读。
- quantity 收货录入整数数量；serialized 收货必须选择/扫描真实单元，不允许只填数量。

### 4.2.6 不可售库存

- 主要区域：全部可管理库存列表、不可售变更详情。
- 筛选：仓库、商品、跟踪模式、是否有不可售、原因、日期。
- 列：仓库、商品、在手、不可售、可售、跟踪模式、最近变更、状态。
- 详情：批次/逐瓶单元、历史变更、原因、来源单据。
- 按钮：
  - quantity：转入不可售、恢复可售，输入正整数和必填原因；
  - serialized：选择/扫描单元后转换；
  - warehouse/admin 可操作，finance/boss 只读。
- 两种转换都二次确认，成功后使库存列表、详情、流水和总览对应缓存失效。

### 4.2.7 销售出库与配货

- 主要区域：待配订单队列、订单详情、预占/分配/出库进度、打包编辑区。
- 筛选：履约仓、订单号、客户、商品、物流方式、占用/待配/已配/已出库/异常状态、日期。
- 列：订单号、履约仓、申请、已占用、已分配、待配、已出库、物流方式、状态、更新时间。
- 详情：
  - 订单业务信息；
  - 每行 requested/reserved/assigned/outbound/shortage 数量；
  - serialized 商品显示分配单元和物流码；
  - 打包数量、物流公司、运单号；
  - warehouse 不显示任何成本。
- 按钮：选择履约仓、分配/更换逐瓶单元、保存打包、确认出库；所有改变库存事实的动作二次确认。
- 销售录单页只提交商品和数量，不展示库存，不选择逐瓶单元。

### 4.2.8 顾客退货收货

- 主要区域：需要实际返货的售后单、收货草稿、已过账只读记录和履约进度；只退款单不进入列表。
- 筛选：售后单号、原订单号、客户、仓库、商品、收货状态和日期。当前仓库/商品/收货状态等只作用于后端最近 100 条真实结果，页面必须持续显示范围阻塞。
- 列：售后单号、原订单、客户、处理方式、收货仓库、应退、累计实收、剩余待收、状态和创建时间。
- 详情：
  - 退货申请行与实收行对照；
  - quantity 本次实际数量、可售/不可售/异常、已有批次和备注；
  - serialized 原订单物流码、扫描码和 matched/unknown/conflict 状态；
  - receipt ID、草稿/已过账/已冲销、仓库和时间；服务端未返回的操作者显示“暂未提供”，不得猜测。
- 按钮：
  - warehouse/admin/super_admin：创建实收草稿、确认收货过账；
  - after_sales：只看与售后单相关的收货进度；
  - finance/boss：只读；finance 退款仍在财务页，boss 列表当前受后端权限阻塞；
  - 已确认记录不修改、不删除；后续如开放冲销必须走真实 REVERSE、必填原因和独立二次确认。
- UI 必须明确区分“保存草稿”和“库存已生效”。

### 4.2.9 商品盘点

- 第 09 条完成状态：QUANTITY 商品已完成真实盘点闭环的前端部分；提交前后都不在客户端改余额，只有后端批准成功返回 POSTED 后才刷新库存事实。
- 主要区域：盘点列表、盘点详情、创建时当前库存预览、现存/不可售数量录入和差异预览。
- 当前真实筛选：仓库、单个商品、状态；跟踪模式、盘点单号和创建/提交日期尚无 stocktake list 服务端参数，不能在当前分页上伪装全量筛选。
- 列/卡片：盘点单号、仓库、商品、模式、账面快照、实盘数、差异、状态。
- 详情：
  - 快照 stockVersion/lastMovementId；
  - 在手和不可售快照、实盘和差异；
  - 逐瓶扫描码、预期状态、匹配状态、实盘 condition；
  - 原因和完整流转人/时间。
- 按钮：warehouse/admin/super_admin 创建草稿、填写并提交；创建按钮在空列表时仍存在。
- 数量使用非负整数，允许 0；不可售不能超过现存；原因必填；提交失败保留输入并阻止重复点击。
- 提交前二次确认固定说明“提交不会立即改变库存，审批通过后才过账”；正式快照和差异以服务端提交响应为准。
- SERIALIZED 商品按 `trackingMode` 阻断汇总数量表单并引导到逐瓶入口；后端扫描 API 已存在，但当前统一逐瓶扫描器尚未接入，因此这是前端缺失，不能称为后端阻塞，也不能生成假物流码。

### 4.2.10 盘点审批

- 主要区域：默认待审批列表、差异详情、审批操作；Windows 为列表+右侧详情，手机为卡片+底部详情。
- 当前真实筛选：仓库、商品、状态；提交人和提交日期明确显示“等待接口”禁用控件，不对当前页做假筛选。
- 列/卡片：盘点单号、仓库、商品、在手差异、状态；详情完整显示不可售差异、提交人和提交时间。
- 详情：完整快照、实盘、逐瓶扫描证据、原因、当前库存是否已变化。
- 按钮：admin/super_admin/boss 可批准或驳回；只有 admin/super_admin 对 POSTED 记录显示必填原因的冲销；boss 无其他数量调整按钮。
- 批准二次确认后由服务端在同一事务复核快照并过账；正常成功直接显示 POSTED，不在客户端伪造 APPROVED。
- 后端返回 `INVENTORY_STOCKTAKE_SNAPSHOT_STALE` 时显示“快照已过期/期间发生出入库，请重新盘点”，重新拉取真实详情，不提供强制覆盖。
- 已审批记录只读；驳回和冲销原因在请求失败后保留；重复批准/并发状态变化使用服务端稳定错误并回拉。

### 4.2.11 预警与规则

- “预警规则”和“活动预警”分成两个子页面或同页两个明确分区，不能把配置列表命名为预警列表。
- 规则筛选：仓库、商品、启用状态；列为仓库、商品、最低可售、启用状态、更新时间。
- 规则按钮：admin/super_admin 新建或编辑阈值、启停；二次确认启停。
- 活动预警筛选和列：仓库、商品、当前可售、阈值、短缺/低库存、触发时间。
- 当前后端没有独立活动预警 endpoint；未接报表前应显示“功能暂不可用/等待接口”，不能使用总览常量 0。

### 4.2.12 库存流水

- 筛选：仓库、商品、movementType、来源单据、操作人、日期、仅冲销。
- Windows 列：时间、仓库、商品、类型、在手变化、占用变化、不可售变化、在途变化、来源、操作人。
- 详情：sourceKey、batchId、serializedUnitId、reservationId、reason、reversalOfMovementId；有权限时显示单位成本和金额。
- 四类 delta 分栏展示并带正负号和“瓶”；不能合并成一个错误的 quantity。
- warehouse 不请求成本字段。

### 4.2.13 库存报表

- 主要区域：报表类型、参数筛选、结果表、导出。
- 筛选按报表类型配置：仓库、商品、日期、状态、分页。
- 结果列使用客户端 allowlist 和 formatter：
  - 数量 -> `N 瓶`
  - 金额分 -> 人民币格式
  - 日期 -> 统一本地时间
  - 状态 -> 中文标签 + 图标/文字
- finance/admin/boss 可用成本报表；warehouse 的请求中不包含成本类报表类型。
- 导出要调用项目现有下载/保存能力并实际写文件；导出中禁用按钮，失败可重试。

## 6. 页面状态设计

所有列表和表单必须统一状态语言，优先复用现有 `LoadingState`、`EmptyState`、`ErrorState`、`StatusTag`、确认弹窗和错误映射。

| 状态 | 页面表现 | 可用操作 | 实现要求 |
| --- | --- | --- | --- |
| 首次加载 | 页面骨架或 `LoadingState`，标题说明加载对象 | 取消导航 | 保留页头，不用全屏空白 spinner |
| 刷新中 | 保留旧数据，刷新按钮转圈/禁用 | 可继续查看 | 不把页面闪回首次加载 |
| 空数据 | `EmptyState` + 原因 + 有权限的主操作 | 新建/刷新 | 筛选栏和主操作不能随空列表消失 |
| 筛选无结果 | 显示已激活条件和“清除筛选” | 清除/修改筛选 | 与系统没有数据区分 |
| 加载失败 | `ErrorState` + 中文错误 + 重试 | 重试/刷新 | 网络、权限、校验、冲突分别映射 |
| 权限不足 | 锁图标 + 当前角色无权说明 | 返回 | 不先请求敏感接口再显示 |
| 后端未实现 | 明确“功能暂不可用/等待接口” | 刷新或返回 | 不用空列表、0 或本地模拟伪装成功 |
| 提交中 | 表单和主按钮禁用，按钮显示进行中 | 可选取消 | 防重复点击，同一命令复用 idempotencyKey |
| 提交成功 | 成功提示 + 局部刷新 + 保留相关上下文 | 查看单据/继续 | 只失效受影响页面，不重置全部导航 |
| 校验失败 | 字段级错误 + 顶部摘要 | 修正后重试 | 保留用户输入；数量/金额/字符串规则明确 |
| 409/快照冲突 | 冲突卡片说明“库存已变化”及影响 | 刷新详情/放弃 | 不自动重放危险命令 |
| 幂等重放 | 显示已处理结果，不重复生成单据 | 查看原结果 | 识别 `replayed`，避免重复成功提示造成误判 |
| 未保存离开 | 二次确认“放弃修改/继续编辑” | 选择 | 新增、编辑、扫描、成本维护均覆盖 |
| 分页加载 | 保留筛选、当前页和总数 | 上一页/下一页/加载更多 | 手机用加载更多，桌面用分页 |

## 6.1 状态视觉规范

- 正常：中文“正常” + check 图标 + success tone。
- 低库存：中文“低库存” + warning 图标 + warning tone。
- 短缺：中文“短缺” + error 图标 + danger tone。
- 不可售：中文“含不可售” + block 图标 + danger/warning tone。
- 待补成本：中文“待补成本” + currency/clock 图标 + warning tone。
- 待审批：中文“待审批” + approval 图标 + info tone。
- 状态不能只靠红黄绿，`StatusTag` 建议增加可选 icon，或用“图标 + StatusTag + 辅助文字”组合。

## 8. 与库管打包页、逐瓶页、售后页的整合

## 8.1 库管打包页

保留 `warehouse_packing` 作为一个可独立打开的工作台，但把它作为仓库管理“销售出库与配货”的同一页面能力，而不是再在 `inventory_workspace_tabs.dart` 写第二套打包：

- 一级角色菜单可继续直达；
- 仓库管理二级导航进入同一个页面/同一个 controller；
- 从总览待办进入时传入筛选条件，而不是复制列表；
- 打包保存、履约仓调整、逐瓶分配、出库确认共享同一订单状态；
- mutation 后使订单队列、库存和总览局部失效。

第 07 条已补 requested/assigned/outbound/unassigned、shortage warning 和 serialized assignment，并停止把 `packageCount` 当“待配数量”。`reservedQty` 仍未由 warehouse actor DTO 返回，页面明确显示“暂未提供”。

## 8.2 茅台逐瓶页

逐瓶库存不是第二套库存系统，应成为 `inventoryTrackingMode == serialized` 的库存详情和作业视图：

- 商品判断只用 `inventoryTrackingMode` 或后端 capability，不使用名称；
- 复用 `InventoryApi` 的仓库、库存详情、调拨、盘点和不可售能力；
- 旧 `BusinessApi` serialized endpoint 如仍需兼容，只作为同一 adapter 内的过渡数据源；
- 页面必须支持 warehouseId；
- 统一 AVAILABLE/RESERVED/OUTBOUND/UNAVAILABLE 等状态；
- quantity 总数和逐瓶单元数要由后端事实一致性校验；
- 手机改卡片和独立详情，不使用横向宽表作为主界面。

不要同时保留“WarehouseManagement 的逐瓶 Tab”和“独立茅台库存页面”两套独立加载状态。迁移期可以两个入口指向同一页面实例/route builder。

## 8.3 售后页

售后业务页负责申请、审核、退款和查看进度；仓库实收工作台负责形成库存事实：

- after_sales 只请求当前售后单的 receipt/fulfillment projection；
- warehouse/admin/super_admin 在“顾客退货收货”工作台创建真实 DRAFT receipt；
- 确认收货时调用 POST 过账，成功后才显示“库存已生效”；
- 当前已确认记录只读；如后续开放冲销，必须调用现有真实 reverse adapter、填写原因并独立二次确认；
- quantity 和 serialized 共用 receipt header，行内按 trackingMode 分流；
- 旧“库管确认收货”写按钮已移除，只保留历史状态字段兼容，不与真实 receipt 形成两套可写状态；
- finance 退款状态读取同一售后单进度，但不调用库存写接口。

## 8.4 销售订单

- 保持当前销售订单只提交商品和数量。
- 删除或改写仍期待 `serializedUnitIds` 的旧 Widget 测试。
- sales 不请求 `/api/inventory/stocks`、逐瓶可售列表、成本或全仓数量。
- 库存预占、逐瓶分配和出库由后端与 warehouse/admin 工作台完成。
