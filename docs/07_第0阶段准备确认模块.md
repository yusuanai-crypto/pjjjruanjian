# 第 0 阶段准备确认模块

## 1. 模块目标

本模块只服务“第 0 阶段：准备和确认”。它用于把开发前必须确认的角色权限、字段、业务规则、页面样式、售后流程、提成积分规则和基础账号准备情况做成可查询、可更新、可汇总的确认清单。

本模块不包含登录、旅行团录入、订单、售后、提成计算、AI 查询、Flutter 页面和数据库迁移。这些属于后续阶段。

## 3. 确认项状态

| 状态 | 说明 |
| --- | --- |
| `pending` | 待确认。 |
| `in_review` | 正在确认或等待业务方复核。 |
| `confirmed` | 已确认。设置该状态时必须提供 `confirmedBy`。 |
| `blocked` | 被外部事项阻塞，例如账号未准备好或规则未收齐。 |

## 4. 接口说明

### 4.1 查询确认项列表

`GET /api/preparation-confirmation/items`

请求参数：

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `status` | query | 否 | 按状态筛选，可选：`pending`、`in_review`、`confirmed`、`blocked`。 |
| `category` | query | 否 | 按分类筛选，可选：`permissions`、`fields`、`business-rules`、`ui-prototype`、`infrastructure`。 |

返回结果：

```json
{
  "data": {
    "items": [
      {
        "id": "roles-permissions",
        "category": "permissions",
        "title": "确认员工角色和权限",
        "description": "确认前台、销售、品鉴师、财务、库管、售后、老板、管理员的可见范围和可修改范围。",
        "requiredEvidence": ["角色权限表", "关键操作权限说明"],
        "sourceDocs": ["docs/01_PRD.md", "docs/02_功能模块拆分.md"],
        "status": "pending",
        "owner": null,
        "notes": "",
        "evidenceLinks": [],
        "confirmedBy": null,
        "confirmedAt": null,
        "updatedAt": null
      }
    ]
  }
}
```

### 4.3 更新单个确认项

`PUT /api/preparation-confirmation/items/:id`

路径参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 确认项 ID，例如 `roles-permissions`、`travel-group-fields`。 |

请求体：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `status` | 否 | 新状态，可选：`pending`、`in_review`、`confirmed`、`blocked`。 |
| `owner` | 否 | 当前负责人。 |
| `notes` | 否 | 确认备注或阻塞原因。 |
| `evidenceLinks` | 否 | 证据链接数组，例如文档路径或会议纪要路径。 |
| `confirmedBy` | 条件必填 | 当 `status` 为 `confirmed` 时必填。 |
| `confirmedAt` | 否 | 确认时间。未传时由服务端自动生成。 |

请求示例：

```json
{
  "status": "confirmed",
  "owner": "project-owner",
  "confirmedBy": "admin",
  "notes": "角色权限已按 PRD 确认。",
  "evidenceLinks": ["docs/01_PRD.md"]
}
```

返回结果：

```json
{
  "data": {
    "item": {
      "id": "roles-permissions",
      "category": "permissions",
      "title": "确认员工角色和权限",
      "description": "确认前台、销售、品鉴师、财务、库管、售后、老板、管理员的可见范围和可修改范围。",
      "requiredEvidence": ["角色权限表", "关键操作权限说明"],
      "sourceDocs": ["docs/01_PRD.md", "docs/02_功能模块拆分.md"],
      "status": "confirmed",
      "owner": "project-owner",
      "notes": "角色权限已按 PRD 确认。",
      "evidenceLinks": ["docs/01_PRD.md"],
      "confirmedBy": "admin",
      "confirmedAt": "2026-06-19T04:00:00.000Z",
      "updatedAt": "2026-06-19T04:00:00.000Z"
    }
  }
}
```

错误返回格式：

```json
{
  "error": {
    "code": "INVALID_STATUS",
    "message": "status must be one of: pending, in_review, confirmed, blocked."
  }
}
```

## 5. 本地运行和测试

启动 API：

```powershell
cd D:\jiangjiu\server\api
npm.cmd start
```

查询确认项：

```powershell
Invoke-RestMethod -Method Get -Uri http://localhost:3000/api/preparation-confirmation/items
```

更新确认项：

```powershell
Invoke-RestMethod `
  -Method Put `
  -Uri http://localhost:3000/api/preparation-confirmation/items/roles-permissions `
  -ContentType 'application/json' `
  -Body '{"status":"confirmed","owner":"project-owner","confirmedBy":"admin","notes":"角色权限已确认。","evidenceLinks":["docs/01_PRD.md"]}'
```

运行测试：

```powershell
cd D:\jiangjiu\server\api
npm.cmd test
```
