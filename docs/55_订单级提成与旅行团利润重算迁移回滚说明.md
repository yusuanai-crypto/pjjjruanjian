# 订单级提成与旅行团利润重算迁移回滚说明

## 目标与口径

- 销售提成仍绑定销售人员。
- 外联提成、组长提成改为订单级规则费用，活跃自动记录的 `target_user_id` 为 `NULL`。
- 自动记录使用 `sales-order:{salesOrderId}:{targetType}:automatic` 作为稳定业务键。重算不删除、不将历史金额改为 0；重复或已失效记录仅标记为非活跃。
- 利润费用包含销售/外联/组长提成、税费、付款手续费、导游日返积分和月返积分。未财务标记订单税费按 0、手续费按付款明细正常计算；只有付款明细缺失/不平、付款方式或手续费率缺失等真实数据问题才阻断手续费。

## 发布前检查

1. 备份 `commission_records`、`sales_orders`、`sales_order_payment_details`、`travel_group_finance_summaries` 和 `guide_points_summaries`。
2. 记录当前应用版本、数据库迁移版本及活跃外联/组长自动记录数。
3. 确认所有有效订单的收款明细合计与订单总额一致，付款方式手续费率已配置；已标记订单另需保留历史费率快照。
4. 先停止旧版本写入提成记录，再执行数据库迁移和回填。

## 部署顺序

1. 执行 Prisma 迁移：

   ```powershell
   npx.cmd prisma migrate deploy
   ```

   迁移 `20260802000300_order_level_automatic_commissions` 只新增可空的 `automatic_scope_key` 和唯一索引，不会删除历史字段或记录。

2. 默认以 dry-run 执行回填：

   ```powershell
   npm.cmd run backfill:order-level-commissions -- --dry-run
   ```

3. 必须人工复核报告中的：

   - `affectedOrderIds`：受影响订单清单；
   - `duplicateRecords`：同一订单、同一费用类型的重复活跃记录；
   - `amountDifferences`：重复记录合计值与保留记录金额的差异。

4. 确认报告后执行实际回填：

   ```powershell
   npm.cmd run backfill:order-level-commissions -- --apply
   ```

5. 再次执行 dry-run。期望 `affectedScopeCount` 为 0；若不为 0，不得继续发布，应先保存两次报告并排查并发写入。
6. 发布后端，再发布 Flutter 客户端。

## 统一重算接口

`POST /api/analytics/travel-group-profits/:travelGroupId/recalculate`

- 仅 `admin` / `super_admin` / `finance` 可执行。
- 每个订单使用独立事务；一单失败不回滚其他已成功订单。
- 返回 `successCount`、`failureCount`、`changedCount`、`unchangedCount`、逐订单 `results`、结构化 `issues` 和重算后 `profit`。
- 写入审计动作 `analytics.travel_group_profit.recalculate`。

利润诊断组件键为 `salesCommission`、`outreachCommission`、`leaderCommission`、`tax`、`paymentServiceFee`、`guideDailyPoints`、`guideMonthlyPoints`。每个组件提供 `status`、`amountCents`、`issues[]`，问题含稳定 `code`、订单定位和 `actionHint`。

## 回滚策略

1. 先回滚应用版本，停止新的订单级业务键写入。
2. 保留 `automatic_scope_key`、`is_active`、`deactivated_at` 以及所有历史记录；默认不执行删列、删索引、删记录或批量覆盖金额。
3. 如业务确认必须恢复单条旧记录，根据 `source_snapshot.orderLevelCommissionMigration` 的保留记录 ID、失效记录 ID、时间和业务键进行人工审核后恢复。
4. 费用快照修复只填充 `NULL`，不覆盖已有历史快照。使用当前付款方式费率补齐历史空值存在口径风险，必须保留发布前备份与重算审计日志。

## 验收要点

- 同一订单、同一自动类型只有一条活跃记录，重复重算不新增记录。
- 外联/组长记录 `targetUserId = null`，0% 有效规则显示为已计算 0 元。
- 修改订单日期后，销售提成重新匹配新日期覆盖的规则。
- 未财务标记本身不影响利润完整性；收款明细缺失/不平、付款方式或手续费率缺失时仅手续费组件阻断并显示“请补齐付款明细或配置付款方式手续费率”。已标记历史订单税率快照缺失时仍按固定 1% 计算。
- 导游日返/月返积分同时进入列表汇总、费用、利润和 Excel 导出。
