# 利润税费、手续费历史回填与回归验收清单

更新日期：2026-07-30

## 1. 适用范围和硬性边界

- 本清单对应 migration：
  `server/api/prisma/migrations/20260729000500_profit_tax_payment_service_fees/migration.sql`。
- 历史回填脚本：
  `server/api/scripts/backfill-profit-fee-snapshots.ts`。
- 脚本默认 dry-run；本文档中的命令不会被应用自动执行。生产
  `--apply` 必须由获授权人员在维护窗口手工执行。
- 只处理 `SalesOrder.financeMark = true` 且税费/手续费快照缺失的订单。
- 不给历史付款方式费率设置猜测值。付款方式当前费率缺失或非法时，整单跳过。
- 历史已确认退款没有 `refundPaymentDetailId` 时，不猜测退款方式、不修改退款记录、不冲减手续费。
- 回填报告只允许订单 ID/单号、付款明细 ID、付款方式 ID/名称快照和汇总金额，不得包含客户姓名、电话、地址。

## 2. 数据口径验收

- [ ] 未财务标记订单的税费和手续费均为 0；即使全局标记过滤关闭也不参与。
- [ ] 已标记订单税率快照为 `0.010000`，税费按有效金额逐订单半入到分。
- [ ] 混合付款按每条付款明细快照独立计算，0% 费率合法。
- [ ] 付款方式改费率、改名或停用后，已有订单快照保持不变。
- [ ] 已标记订单付款方式或金额修改被阻止；取消标记后重新标记才使用当前费率。
- [ ] 当天退款以 `Asia/Shanghai` 判断，只扣指定付款明细手续费基数，多笔当天退款累计。
- [ ] 跨天退款不冲减手续费；跨天全额退款税费为 0、手续费保留。
- [ ] 未确认或已取消财务确认的退款不生效；重新确认按新的后端实际时间判断。
- [ ] 缺少税率/费率/基数快照时返回 `PAYMENT_SERVICE_FEE_SNAPSHOT_MISSING`，团状态为 `incomplete`、`estimatedProfitCents = null`。
- [ ] 总费用增加税费和手续费；有效销售额、商品成本、物流费、固定费用、提成、返点原口径不变。

## 3. 迁移和回填步骤

### 3.1 上线前

1. 进入维护窗口，暂停订单财务标记、付款明细修改、付款方式费率修改和售后财务确认。
2. 备份 MySQL，并在同版本临时库验证恢复。
3. 发布包含 nullable 新字段、后端兼容读取和回填脚本的版本。
4. 在 `D:\jiangjiu\server\api` 执行 Prisma migration 和 Client 生成：

```powershell
npm.cmd run prisma:migrate:deploy
npm.cmd run prisma:generate
```

5. 由财务逐一确认当前仍被历史订单引用的付款方式费率；不确定的费率保持 `null`，不得为了让回填通过而猜测。

### 3.2 Dry-run（默认且必须先执行）

```powershell
cd D:\jiangjiu\server\api
npm.cmd run backfill:profit-fee-snapshots -- --dry-run --report ".\.private\backfill-reports\profit-fee-dry-run.json"
```

审核报告：

- [ ] `mode = DRY_RUN`、`appliedOrderCount = 0`。
- [ ] `scannedOrderCount` 是全部已标记订单数。
- [ ] `snapshotMissingOrderCount` 是快照缺失候选订单数。
- [ ] `backfillableOrderCount` 等于审核批准的整单回填数。
- [ ] `missingRatePaymentMethods`、`missingRateOrders` 已交财务确认；这些订单不会部分写入。
- [ ] `historicalRefundPaymentDetailUnknownOrders` 已备案，且确认不对这些历史退款猜测付款方式。
- [ ] 报告抽查不含客户姓名、电话、地址。

### 3.3 Apply（只允许人工显式执行）

确认备份、维护窗口、dry-run 报告和付款方式费率后，才执行：

```powershell
cd D:\jiangjiu\server\api
npm.cmd run backfill:profit-fee-snapshots -- --apply --report ".\.private\backfill-reports\profit-fee-apply.json"
```

Apply 行为：

- 每单事务内二次读取 `financeMark`、缺失快照、付款明细和当前付款方式费率。
- 税率只填 `null` 为 `0.010000`；费率和基数只填 `null`；已有快照不覆盖。
- `profitFeeSnapshottedAt` 只在缺失时写执行时间。
- `profitFeeSnapshottedById` 不猜测历史操作人，保持 nullable；以 JSON 报告审计本次历史回填。
- 某单二次校验失败或写入异常时，该单事务不产生部分写入，并进入跳过/失败报告。
- 脚本不更新 `financeMark`、`markedAt`、`markedById`、订单金额、利润旧字段或任何售后退款字段。

### 3.4 Apply 后核验和幂等

再次执行 dry-run：

```powershell
npm.cmd run backfill:profit-fee-snapshots -- --dry-run --report ".\.private\backfill-reports\profit-fee-post-check.json"
```

- [ ] 已成功回填订单不再进入 `snapshotMissingOrderCount`。
- [ ] 剩余候选仅为缺失/非法当前费率或执行失败的订单，且原因可追踪。
- [ ] 再次执行 `--apply` 时已完成订单的 `appliedOrderCount = 0`，已有快照时间、税率、费率和基数均不刷新。
- [ ] Apply 报告已保存到受限目录，访问权限和保留期限已登记。

## 7. 回滚边界和剩余风险

- migration 为扩展式 nullable 字段迁移。应用故障时优先停止写入并回滚应用，保留新增字段和已生成快照，不执行破坏性 down migration。
- 已回填费率来自“执行时当前 PaymentMethod”，不是可证明的历史真实费率。财务必须在 apply 前审核；不确定则保持 null 并接受该订单利润 `incomplete`。
- `profitFeeSnapshottedById` 对历史回填保持 null，审计依赖受限 JSON 报告；报告丢失会降低回填执行人的可追溯性。
- 扫描和逐单事务之间仍可能发生并发费率/标记变化；必须使用维护窗口。脚本在事务内二次校验并只填 null，但不代替业务停写。
- 历史无付款明细归属的退款故意不冲减手续费，可能与线下实际通道不同；没有可靠证据时不允许自动修正。
