## 1. 阶段目标与业务口径

### 1.1 商品主数据

- 商品是独立主数据，不再由订单、品酒或规则临时输入名称。
- 字段包含名称、规范化名称、单位、启用状态、备注和创建/修改审计字段，不包含排序字段。
- 名称 trim 后全局唯一；`normalizedName` 使用 NFKC、去首尾空格、去内部空白和小写化做规范去重。
- 商品不提供物理删除 API，只能启用/停用。
- 停用商品不进入新业务选择器，历史快照继续显示。

### 1.2 三类成本彻底分离

| 成本 | 存储/维度 | 用途 |
| --- | --- | --- |
| 商品实际成本 | `ProductActualCost`，商品 + 生效区间 | 订单成本快照和毛利 |
| 销售扣单成本 | `SalesDeductionRule`，商品 + 生效区间 | 员工提成扣单 |
| 旅行社扣酒成本 | `AgencyDeductionRule`，旅行社 + 商品 + 生效区间 | 旅行社返利/上单金额 |

三者不互相复制、不回退代用、不混合计算。

### 1.3 权限

- admin、finance：可查看和管理商品、实际成本及两类扣减成本。
- boss 和其他角色：不可访问成本、毛利或成本覆盖接口。
- 有相应业务表单权限的已登录角色：可调用 `GET /api/products/options`，但只能获得启用商品的 `id/name/unit`。
- Flutter 菜单隐藏不作为唯一保护；Controller 认证、Service 角色检查和页面内角色拦截同时存在。

## 2. 数据模型与迁移

### 2.1 新模型

- `Product`：`id/name/normalizedName/unit/isActive/notes/createdById/updatedById/createdAt/updatedAt`。
- `ProductActualCost`：`id/productId/costCents/effectiveFrom/effectiveTo/isActive/notes` 及审计字段。
- 同一商品启用的实际成本区间不得重叠；Service 和 MySQL trigger 均校验。

### 2.2 旧模型兼容增量

- `SalesOrderItem`：可空 `productId`、`unit`、`actualUnitCostCents`、`actualCostSubtotalCents`、`grossProfitCents`。
- `TravelGroupTastingItem`、`SalesDeductionRule`、`AgencyDeductionRule`：可空 `productId`。
- 四个商品关联均使用 `onDelete: SetNull`，旧 `productName` 和单位快照保留。
- 迁移不删除或重写旧业务数据，不为旧订单伪造成本。

迁移：`server/api/prisma/migrations/20260711000100_stage10_product_cost_schema/migration.sql`。

## 3. 首批 16 项商品和回填

- 唯一原始来源是仓库根目录 `商品实际成本.xlsx`。
- 已核验数据固化在 `server/api/prisma/stage10-product-seed-data.js`，服务启动时不读 Excel。
- “商品名/单位”按 `/` 拆分，元金额精确转为整数分。
- 商品库正式启用日配置为 `STAGE10_PRODUCT_CATALOG_GO_LIVE_DATE = '2026-07-11'`。
- seed 和历史关联回填幂等；输出 matched/skipped/warnings；匹配不到、歧义或冲突不猜测。
- 不回填旧订单的实际成本、成本小计或毛利。

## 4. 后端 API

### 4.1 商品与实际成本

- `GET /api/products`
- `POST /api/products`
- `GET /api/products/:id`
- `PATCH /api/products/:id`
- `PATCH /api/products/:id/status`
- `GET /api/products/:id/actual-costs`
- `POST /api/products/:id/actual-costs`
- `PATCH /api/product-actual-costs/:id`
- `PATCH /api/product-actual-costs/:id/status`
- `GET /api/products/options`：只返回启用商品的 `id/name/unit`。

不存在商品 DELETE 路由。商品和实际成本变更写入 `operation_logs`。

### 4.2 订单和品酒快照

- 新建/替换明细必须传 `productId`，自由 `productName` 写入被拒绝。
- 服务端读取商品名称和单位，忽略/拒绝客户端伪造的名称、单位和成本。
- 订单按 `orderDate` 匹配有效实际成本，写入单位成本、成本小计和毛利快照。
- 商品、订单日期或数量变化时重建快照；只改备注/客户/成交单价时不重写实际成本快照。
- 品酒明细只快照名称和单位，不写实际成本或毛利。

### 4.3 扣减规则与计算

- 销售扣单规则新建/编辑接收 `productId`，服务端写入 `productName` 快照。
- 旅行社扣酒规则新建/编辑接收 `agencyId + productId`。
- 计算优先用 `productId`；只有历史记录缺少 ID 时才使用规范化 `productName` 兼容匹配。
- 销售扣单、旅行社扣酒仍按各自规则独立计算，商品实际成本字段不改变提成、返利或积分结果。

## 5. 毛利和成本覆盖

- 订单成本只读 `actualCostSubtotalCents` 快照，绝不读当前商品成本回算。
- 覆盖状态为 `complete | partial | unavailable`。
- `complete`：返回完整 `grossProfitCents`。
- `partial` / `unavailable`：完整毛利为 `null`，同时返回覆盖率、缺口行/订单数、缺口金额和 warning。
- 退款暂无商品级退货数量，不虚构成本冲回；净毛利只能以 `estimatedGrossProfitCents` 显示，并返回 `REFUND_COST_REVERSAL_UNAVAILABLE`。
- 财务概览、订单毛利详情和 analytics 毛利接口只允许 admin/finance。

## 6. Flutter 实现

### 6.1 商品管理

- 后端菜单 ID：`product_management`，只分配给 admin/finance。
- shared fallback、destinations、page_factory 和菜单契约已同步。
- 页面内再做角色拦截，不依赖菜单隐藏。
- 桌面端为列表 + 详情双栏，窄屏为商品卡片 + 独立详情区。
- 支持搜索、状态筛选、新增、编辑、启停、实际成本历史及两类扣减成本入口。
- 元金额最多两位小数，不使用浮点数转换，提交前精确转分。

### 6.2 统一商品选择器

- 订单录入/编辑、品酒明细、销售扣单规则、旅行社扣酒规则均调用 `GET /api/products/options`。
- 显示“商品名称 · 单位”，可搜索，不允许自由输入名称。
- Flutter `ProductOptionRecord` 只解析 `id/name/unit`；即使响应夹带成本字段也不进入 UI 状态。
- 加载失败、无启用商品、原商品已停用、历史记录缺 `productId` 均有明确状态。
- 新提交只发送 `productId`，不发送名称、单位或实际成本。

## 11. 2026-07-23 茅台逐瓶库存扩展

本节替代早期“单品库存”设想。页面名称为“茅台”，底层仍是可复用的逐瓶库存模型，不通过商品名称判断库存业务。

### 11.1 商品与逐瓶主数据

- `Product.inventoryTrackingMode` 支持 `NONE`、`SERIALIZED`；迁移创建或更新统一“茅台”主商品为 `SERIALIZED`。
- 每瓶由 `SerializedInventoryUnit` 保存 `moutaiName`、出厂日期、生产批次、批次序号、原始物流码和逐瓶进货价。
- 批次、序号和物流码始终按字符串保存；规范化物流码全局唯一，前导零不丢失。
- 历史兼容字段在数据库层允许为空；新建和普通编辑接口要求完整生产资料。资料不完整的历史记录可查询，但不能导出或被订单选择。
- 库管录入的完整生产资料进入 `PENDING_COST`；财务或管理员补齐非负进货价后转为 `AVAILABLE`。
- 已分配库存只能通过“资料纠错”接口修改，必须填写原因并记录修改前后数据。

### 11.2 权限与数据最小化

- admin：管理生产资料、成本和导出。
- finance：编辑生产资料与成本，可将 `PENDING_COST` 补齐为 `AVAILABLE`。
- warehouse：编辑生产资料、批量入库和导出，但库存列表、详情、操作日志 DTO、订单和导出结果均不返回进货价。
- sales：只通过订单可售库存接口取得选择所必需的库存 ID、名称、物流码、日期、批次和序号，不返回成本、状态、审计字段或订单关联。
- Product 名称只能沿用商品管理权限修改；“茅台”逐瓶页面不提供修改全局 `Product.name` 的入口。

### 11.3 订单占用与成本快照

- 仅 `SERIALIZED` 商品显示“选择物流码”；数量严格等于 `serializedUnitIds.length`，由选择数量自动生成且输入框只读。
- 同一订单明细只能选择规范化后相同 `moutaiName` 的库存；不同名称或年份必须拆成不同明细。
- 客户端只提交库存 ID，不提交进货价。保存事务内重新校验 `AVAILABLE`、商品归属、资料完整性和逐瓶成本。
- 占用采用条件更新；并发抢占时只有一个事务成功，失败返回 `INVENTORY_UNIT_UNAVAILABLE`。
- `actualCostSubtotalCents` 为所选每瓶成本快照之和，`grossProfitCents = subtotalCents - actualCostSubtotalCents`。
- 编辑按 retained、added、removed 差异同步：保留瓶不改成本快照，新增瓶按当前逐瓶成本快照，移除瓶恢复可售。只改客户、售价或备注不会改变库存选择和原成本快照。
- 旧订单不伪造逐瓶关联，仍可按原快照查询。

### 11.4 物流单 Word 导出

- 接口：`POST /api/serialized-inventory/export-moutai-logistics-docx`，请求体为 `{"unitIds":["..."]}`，单次 1 至 100 瓶。
- 只允许 admin、finance、warehouse；重复 ID、记录不存在、资料不完整或 `VOID` 均拒绝。
- 模板位于 `server/api/assets/templates/moutai-logistics-sheet.docx`，固定 SHA-256 为 `fff3188e073183db78bb70859718900a1662036e1ca29d89742f9009992ee5aa`。
- 运行时校验模板哈希，只修改 `word/document.xml` 的五个正文槽位；其他 OOXML 文件保持模板内容。
- 按请求顺序克隆页面，一瓶一页、页面间显式分页、文末仅一个 `sectPr`。用户文本做 XML 转义，不写入成本、数据库 ID 或内部状态。
- 响应为内存 Buffer，文件名为 `茅台物流单_YYYYMMDD_共N瓶.docx`，不在服务端长期保存。
- Flutter 复用现有二进制下载和 `FilePicker.saveFile` 流程；无选择、权限不足、资料不完整、模板损坏和本地保存失败均显示中文提示。

### 11.5 模板与样例验收

- 原附件只读复制，源文件与项目模板哈希一致，开发和运行时均不依赖 `D:\备份`。
- 自动样例脚本：在 `server/api` 执行 `npm run sample:moutai-logistics`。
- 样例覆盖单瓶、两瓶合并、较长生肖名称及带前导零字段。
- 自动测试校验 ZIP 可打开、`document.xml` 合法、字段顺序、分页数、唯一末尾 `sectPr`、特殊字符转义和内部字段不泄露。
- Word/LibreOffice 的逐页视觉验收仍须在具备 Office 软件的环境按第 42 号清单执行，不能仅以 XML 结构测试代替。
