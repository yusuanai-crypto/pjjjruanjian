# 第 10 阶段：旅行团利润分析开发文档

更新日期：2026-08-03

## 1. 业务边界与权限变更

本需求是对原“boss 不可查看成本、毛利”规则的有意、受限变更：

- `boss`、`admin`、`super_admin` 可以进入独立的“利润分析”页面，并调用 `GET /api/analytics/travel-group-profits`。
- 老板只能看到旅行团级的有效销售额、费用汇总、预估利润、利润率和核算状态。
- 新接口不返回商品单位成本、商品级成本明细、客户隐私、提成领取人、规则快照、规则内部扣减成本或 Prisma 原始关联对象。
- `finance` 不能进入新页面，也不能调用新接口；但其原有 `/api/finance/profit-overview`、订单毛利、商品成本和 `/api/analytics/profit-overview` 权限保持不变。
- 菜单、Flutter destinations、页面和后端 service 均独立校验角色；菜单隐藏不作为后端授权依据。

权限矩阵：

| 角色 | 新菜单/页面 | 新接口 | 原财务利润能力 |
| --- | --- | --- | --- |
| super_admin | 允许 | 允许 | 按管理员 |
| admin | 允许 | 允许 | 保持不变 |
| boss | 允许，只读旅行团汇总 | 允许 | 不获得商品级成本能力 |
| finance | 禁止 | 403 | 保持不变 |
| sales/front_desk/warehouse/after_sales/taster | 禁止 | 403 | 保持原角色边界 |

匿名调用新接口返回 401。

## 2. 利润口径

所有金额使用整数分：

```text
totalExpenseCents
= actualProductCostCents
+ logisticsFeeCents
+ parkingFeeCents
+ cigaretteFeeCents
+ salesCommissionCents
+ leaderCommissionCents
+ outreachCommissionCents
+ tasterCommissionCents
+ dailyAgencyRebateCents
+ monthlyAgencyRebateCents
+ taxFeeCents
+ paymentServiceFeeCents

estimatedProfitCents = effectiveSalesAmountCents - totalExpenseCents
```

- 有效订单仅为 `VALID`、`PARTIAL_REFUND`，并扣除财务已确认退款；有效金额为 0 的订单不计入。
- 商品成本只读取 `SalesOrderItem.actualCostSubtotalCents` 历史快照，不读取当前 `ProductActualCost` 回算历史订单。
- 物流费只汇总有效订单的 `SalesOrder.logisticsFeeCents`。
- 停车费读取 `TravelGroup.parkingFeeCents` 创建时快照，当前固定为 500 分；以后规则变化不回算历史旅行团。
- 香烟费用读取 `TravelGroup.cigaretteFeeCents`，由前台录入；`null` 表示缺失，不能按 0 处理。
- 销售、组长、外联和品鉴师提成使用 `CommissionRecord.amountCents`。兼容字段 `employeeCommissionCents` 是前三类提成之和；总费用使用它时不得再次重复加入三项分类金额。
- 日返/月返优先使用 `TravelGroupFinanceSummary` 的权威汇总；汇总缺失时才回退 `CommissionRecord.pointsCents`，并返回 `FINANCE_SUMMARY_MISSING`。
- 销售扣单成本和旅行社扣酒成本只用于提成/返点基数，不从利润中再次扣除。
- `SalesOrder.financeMark` 只控制税费：未标记订单税费固定为 0，已标记订单按有效金额的固定 1% 逐订单半入到分；已标记历史订单即使税率快照缺失也按系统固定 1% 兼容计算。新完成财务标记仍保存 `0.010000` 税率快照。
- 付款手续费与订单是否财务标记无关，所有有效状态订单都按每条 `SalesOrderPaymentDetail` 独立计算。已有费率/基数快照时优先使用；未标记订单通常没有快照，此时分别回退当前 `PaymentMethod.serviceFeeRate` 和付款明细 `amountCents`。
- 手续费公式为 `max(适用付款基数 - 已确认当天指定明细退款, 0) × 适用手续费率`，逐明细半入、四舍五入到分后再汇总。0% 费率是合法值；跨天退款等既有退款口径不变。
- 上述订单级口径独立于全局 `onlyShowMarkedRecords`；全局开关只按既有 scope 控制基础数据可见性。
- 税率、手续费率和金额运算使用十进制字符串解析、定点整数或 `BigInt`，不得使用 JavaScript 浮点金额计算。
- 预估利润允许为负数。

## 3. 不完整数据和退款

- `complete`：有有效销售、商品成本快照完整且没有估算风险。
- `estimated`：成本完整，但存在退款成本无法冲回、待确认退款或财务汇总回退等估算风险。
- `incomplete`：任意有效订单明细缺少成本快照、香烟费用缺失，或付款明细、付款方式、手续费率确实缺失；`estimatedProfitCents` 必须为 `null`。未财务标记和已标记历史订单税率快照缺失均不单独阻断利润。手续费无法计算时返回手续费专属诊断，客户端提示“请补齐付款明细或配置付款方式手续费率”，不能按 0 猜测。
- `no_sales`：无有效销售且香烟费用完整；停车费、香烟费用及其他已发生费用仍计入总费用，`estimatedProfitCents = 0 - totalExpenseCents`，利润率为 `null`。

部分退款缺少商品级退货数量时不虚构成本冲回，返回 `REFUND_COST_REVERSAL_UNAVAILABLE`。待确认退款不提前扣除，返回 `PENDING_REFUND_CONFIRMATION`。财务取消确认后，该退款不再参与有效销售额、税费或手续费扣减；重新确认时以后端实际确认时间重新判断当天/跨天。只要汇总中存在有销售额的 `incomplete` 旅行团，汇总预估利润和利润率均为 `null`；`knownEstimatedProfitCents` 仅表示其余已知旅行团的合计。

### 3.1 当天退款和跨天退款

- “当天”由后端以 `Asia/Shanghai` 自然日比较 `AfterSalesOrder.refundOccurredAt` 与源订单 `SalesOrder.orderDate`；客户端日期不参与判定。
- 当天退款必须指定属于源订单的 `refundPaymentDetailId`，并记录付款方式名称快照；同一付款明细的多笔已确认当天退款累计扣减手续费基数，累计金额不得超过原付款明细金额。
- 跨天退款不要求付款明细，`deductsPaymentServiceFee = false`，不改变手续费。即使跨天全额退款使税费变为 0，原付款手续费仍保留。
- 历史已确认退款若没有 `refundPaymentDetailId`，一律不冲减付款手续费，也不得按名称、金额或付款顺序猜测退款方式。

## 4. 查询与展示

- 日期按 `TravelGroup.visitDate` 筛选；团内订单不按订单日期二次过滤。
- 以旅行团为根，确保无订单旅行团也返回。
- 支持本年、本月、上个月、近 10 天、昨日、今日和自定义日期。
- 支持团号/旅行社/导游/品鉴师搜索，状态筛选，日期/销售额/利润/利润率排序及分页。
- 默认本月、到店日期倒序、每页 50，最大 200。
- 全局标记查询开启时复用 Analytics 的旅行团与订单标记 scope。
- 桌面显示宽表格，窄屏显示卡片；点击行只展示旅行团级费用汇总。费用明细在原费用项目后展示税费和手续费，可按 `paymentMethodId + 名称快照 + 适用费率（历史快照或当前回退值）` 展开付款方式手续费明细；同一付款方式的不同适用费率分行展示。
- 总费用、预估利润和利润率直接显示后端结果，Flutter 不重复计算。
- `GET /api/analytics/travel-group-profits/export` 继承页面日期、搜索、状态和排序条件，不受分页限制，使用既有导出行数上限，生成“旅行团利润”“订单税费手续费”“付款方式手续费明细”三个工作表。
- 页面接口、导出文件和历史回填报告均不得返回或写入客户姓名、电话、地址、商品成本规则快照等受限信息。

## 6. 财务标记快照

- 订单由未标记变为已标记时，在同一数据库事务中读取全部付款明细和当前 `PaymentMethod.serviceFeeRate`。任一方式费率为 `null` 时返回 `PAYMENT_METHOD_SERVICE_FEE_RATE_REQUIRED`，整单不产生部分快照。
- 成功标记写入 `SalesOrder.taxRateSnapshot = 0.010000`、`profitFeeSnapshottedAt`、`profitFeeSnapshottedById`，并为每条付款明细写入费率和付款金额快照。
- 重复提交已标记状态幂等，不刷新快照；取消后重新标记使用当时最新付款方式费率并覆盖快照。
- 付款方式费率可为 0，`null` 表示未配置；停用或修改当前费率不改写历史订单快照。
- 已标记订单修改付款方式或付款金额必须先取消订单财务标记，不能静默套用新费率。

## 7. 历史快照回填

脚本：`server/api/scripts/backfill-profit-fee-snapshots.ts`

- 默认 `DRY_RUN`，只有显式 `--apply` 才写数据库；未知参数直接报错。
- 扫描范围仅为 `financeMark = true` 的订单，处理范围进一步限定为税率、快照时间或任一付款明细手续费快照缺失的订单。
- 未财务标记订单不需要回填税率或手续费快照；查询时用当前付款方式费率和付款明细金额兼容计算。
- 税率缺失时写 `0.010000`；付款明细费率缺失时读取当前 `PaymentMethod.serviceFeeRate`，付款基数缺失时读取该明细当前 `amountCents`。
- 任一当前费率缺失或非法时整单跳过并报告；已存在的税率、费率、基数和快照时间不覆盖。
- 回填时间写实际执行时间。`profitFeeSnapshottedById` 不猜测历史操作人，保持 nullable；本次执行由不含客户隐私的 JSON 报告审计。
- 历史退款没有 `refundPaymentDetailId` 时只报告，不更新退款记录，也不冲减手续费。
- 报告包含扫描数、快照缺失数、可回填数、实际回填数、缺失/非法费率付款方式、缺失费率订单、无法确定付款方式的历史退款订单和事务失败订单；只包含订单标识、付款方式快照与汇总金额。
- 每个订单在独立事务中二次读取和校验；写入只填 `null`。重复执行不会刷新已有快照，具备幂等性。

执行命令、生产顺序、回滚边界和逐项验收见 `docs/53_利润税费手续费历史回填与回归验收清单.md`。
