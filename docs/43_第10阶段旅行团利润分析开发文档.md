# 第 10 阶段：旅行团利润分析开发文档

更新日期：2026-07-24

## 1. 业务边界与权限变更

本需求是对原“boss 不可查看成本、毛利”规则的有意、受限变更：

- `boss`、`admin`、`super_admin` 可以进入独立的“利润分析”页面，并调用 `GET /api/analytics/travel-group-profits`。
- 老板只能看到旅行团级的有效销售额、费用汇总、预估利润、利润率和核算状态。
- 新接口不返回商品单位成本、商品级成本明细、客户隐私、提成领取人、规则快照、规则内部扣减成本或 Prisma 原始关联对象。
- `finance` 不能进入新页面，也不能调用新接口；但其原有 `/api/finance/profit-overview`、订单毛利、商品成本和 `/api/analytics/profit-overview` 权限保持不变。
- 菜单、Flutter destinations、页面和后端 service 均独立校验角色；菜单隐藏不作为后端授权依据。

权限矩阵：

| 角色 | 新菜单/页面 | 新接口 | 原财务利润能力 |
| --- | --- | --- | --- |
| super_admin | 允许 | 允许 | 按管理员 |
| admin | 允许 | 允许 | 保持不变 |
| boss | 允许，只读旅行团汇总 | 允许 | 不获得商品级成本能力 |
| finance | 禁止 | 403 | 保持不变 |
| sales/front_desk/warehouse/after_sales/taster | 禁止 | 403 | 保持原角色边界 |

匿名调用新接口返回 401。

## 2. 利润口径

所有金额使用整数分：

```text
totalExpenseCents
= actualProductCostCents
+ logisticsFeeCents
+ parkingFeeCents
+ cigaretteFeeCents
+ salesCommissionCents
+ leaderCommissionCents
+ outreachCommissionCents
+ tasterCommissionCents
+ dailyAgencyRebateCents
+ monthlyAgencyRebateCents

estimatedProfitCents = effectiveSalesAmountCents - totalExpenseCents
```

- 有效订单仅为 `VALID`、`PARTIAL_REFUND`，并扣除财务已确认退款；有效金额为 0 的订单不计入。
- 商品成本只读取 `SalesOrderItem.actualCostSubtotalCents` 历史快照，不读取当前 `ProductActualCost` 回算历史订单。
- 物流费只汇总有效订单的 `SalesOrder.logisticsFeeCents`。
- 停车费读取 `TravelGroup.parkingFeeCents` 创建时快照，当前固定为 500 分；以后规则变化不回算历史旅行团。
- 香烟费用读取 `TravelGroup.cigaretteFeeCents`，由前台录入；`null` 表示缺失，不能按 0 处理。
- 销售、组长、外联和品鉴师提成使用 `CommissionRecord.amountCents`。兼容字段 `employeeCommissionCents` 是前三类提成之和；总费用使用它时不得再次重复加入三项分类金额。
- 日返/月返优先使用 `TravelGroupFinanceSummary` 的权威汇总；汇总缺失时才回退 `CommissionRecord.pointsCents`，并返回 `FINANCE_SUMMARY_MISSING`。
- 销售扣单成本和旅行社扣酒成本只用于提成/返点基数，不从利润中再次扣除。
- 预估利润允许为负数。

## 3. 不完整数据和退款

- `complete`：有有效销售、商品成本快照完整且没有估算风险。
- `estimated`：成本完整，但存在退款成本无法冲回、待确认退款或财务汇总回退等估算风险。
- `incomplete`：任意有效订单明细缺少成本快照，或香烟费用缺失；`estimatedProfitCents` 必须为 `null`。香烟费用缺失时返回 `CIGARETTE_FEE_MISSING`，并优先于 `no_sales` 判定。
- `no_sales`：无有效销售且香烟费用完整；停车费、香烟费用及其他已发生费用仍计入总费用，`estimatedProfitCents = 0 - totalExpenseCents`，利润率为 `null`。

部分退款缺少商品级退货数量时不虚构成本冲回，返回 `REFUND_COST_REVERSAL_UNAVAILABLE`。待确认退款不提前扣除，返回 `PENDING_REFUND_CONFIRMATION`。只要汇总中存在有销售额的 `incomplete` 旅行团，汇总预估利润和利润率均为 `null`；`knownEstimatedProfitCents` 仅表示其余已知旅行团的合计。

## 4. 查询与展示

- 日期按 `TravelGroup.visitDate` 筛选；团内订单不按订单日期二次过滤。
- 以旅行团为根，确保无订单旅行团也返回。
- 支持本年、本月、上个月、近 10 天、昨日、今日和自定义日期。
- 支持团号/旅行社/导游/品鉴师搜索，状态筛选，日期/销售额/利润/利润率排序及分页。
- 默认本月、到店日期倒序、每页 50，最大 200。
- 全局标记查询开启时复用 Analytics 的旅行团与订单标记 scope。
- 桌面显示宽表格，窄屏显示卡片；点击行只展示旅行团级费用汇总。费用明细依次展示商品实际成本、物流费、停车费、香烟费用、销售提成、组长提成、外联提成、品鉴师提成、旅行社日返、旅行社月返、总费用、预估利润和利润率，不展示个人领取人或规则快照。
