# 项目目录结构

本文记录第 1 阶段完成后的实际目录结构，并标注后续阶段预留位置。当前项目采用一个 Flutter 客户端、一个 NestJS API、一个 MySQL 数据库和一个 Dart 共享包的结构。

## 1. 根目录

```text
jiangjiu/
  apps/
    mobile_desktop/
  assets/
    branding/
  docs/
  packages/
    shared/
  server/
    api/
  DEV_LOG.md
```

目录说明：

| 目录 | 当前用途 |
| --- | --- |
| `apps/mobile_desktop/` | Flutter 手机和 Windows 客户端 |
| `assets/branding/` | 品牌图标和视觉资源 |
| `docs/` | 产品、技术、阶段和接口文档 |
| `packages/shared/` | Flutter/Dart 共享常量和格式化工具 |
| `server/api/` | NestJS + Prisma 后端 API |
| `DEV_LOG.md` | 开发日志 |

当前尚未创建 `deploy/`。生产部署、Nginx、Docker Compose、备份恢复脚本留到第 10 阶段。

关键文件：

| 路径 | 说明 |
| --- | --- |
| `lib/main.dart` | Flutter 入口 |
| `lib/app/app.dart` | 应用根组件，负责启动会话恢复、登录态切换和 Shell |
| `lib/app/destinations.dart` | 将后端菜单映射为客户端导航入口 |
| `lib/app/page_factory.dart` | 根据导航 ID 创建页面 |
| `lib/app/theme.dart` | 客户端主题 |
| `lib/core/api/api_client.dart` | 原生 Dart HTTP JSON 客户端 |
| `lib/core/auth/auth_service.dart` | 调用 `/api/auth/login` 和 `/api/auth/me` |
| `lib/core/auth/auth_controller.dart` | 登录、登出、本地 token 恢复 |
| `lib/core/config/app_config.dart` | 默认 API 地址和 `JIANGJIU_API_BASE_URL` 配置 |
| `lib/core/storage/session_storage.dart` | 使用 `shared_preferences` 保存 token 和服务器地址 |
| `lib/features/login/login_page.dart` | 已接真实登录接口 |
| `lib/features/*` | 第 2 阶段 UI 骨架，多数页面仍是假数据 |

当前 Flutter 状态：

- 登录页已接后端 `/api/auth/login`。
- App 启动会用本地 token 调 `/api/auth/me` 恢复会话。
- 登录后菜单来自后端返回的 `menus`，再映射到客户端页面。
- 旅行团、订单、售后、财务、库管、提成、统计、AI 页面仍是 UI 骨架和假数据。

### 3.3 common 层

```text
common/
  filters/
    api-exception.filter.ts
  guards/
    auth-user.guard.ts
    roles.guard.ts
  interceptors/
    api-response.interceptor.ts
  pipes/
    request-validation.pipe.ts
  errors.js
  http.js
  request-ip.ts
```

说明：

- `api-response.interceptor.ts`：把成功响应统一包成 `{ data: ... }`。
- `api-exception.filter.ts`：把异常统一包成 `{ error: { code, message } }`。
- `request-ip.ts`：提取操作日志 IP。
- `errors.js`、`http.js`：旧 JS 工具仍被部分 Nest service 复用，暂不删除。

## 7. 旧文件状态

### 7.1 旧 Node HTTP 文件

以下文件已不是当前默认运行路径：

- `server/api/src/main.js`
- `server/api/src/app.js`
- `server/api/src/modules/*/*.controller.js`

当前默认运行路径是 NestJS：

- `server/api/src/main.ts`
- `server/api/src/app.module.ts`
- `*.nest.controller.ts`
- `*.nest.service.ts`

旧入口可通过 `npm.cmd run start:legacy` 对照调试，但新开发不要在旧控制器中添加业务接口。

### 7.2 旧 JSON 仓储和数据

第 1 阶段账号、系统设置、操作日志当前以 MySQL + Prisma 为主。以下旧 JSON 仓储不是主路径：

- `server/api/src/modules/users/users.repository.js`
- `server/api/src/modules/settings/settings.repository.js`
- `server/api/src/modules/operation-logs/operation-log.repository.js`

第 0 阶段仍保留 JSON 数据：

- `server/api/data/preparation-confirmations.json`

旧第 1 阶段 JSON 文件如果从备份中出现，只作为迁移来源：

- `users.json`
- `system-settings.json`
- `operation-logs.json`

迁移工具：

```text
server/api/scripts/migrate-legacy-json.js
```

## 8. 第一版不要过度拆分

当前仍建议保持：

- 一个 Flutter App。
- 一个 NestJS API。
- 一个 MySQL 数据库。
- 一个 Dart 共享包。

等旅行团、订单、售后、提成、统计、AI 等真实业务跑通后，再根据规模决定是否拆服务、拆包或引入更复杂的部署结构。
