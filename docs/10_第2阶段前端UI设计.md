# 第 2 阶段前端 UI 设计

## 1. 本次实现范围

本阶段新增 Flutter 客户端页面骨架和设计系统。当前登录和会话恢复已经接入第 1 阶段后端接口，其余业务页面仍主要覆盖页面结构、交互路径、假数据展示和组件复用，不实现真实业务保存、查询、导出、二维码生成和 AI 查询。

新增目录：

```text
apps/mobile_desktop/
packages/shared/
```

## 2. Flutter 客户端结构

```text
apps/mobile_desktop/
  lib/
    main.dart
    app/
      app.dart
      destinations.dart
      page_factory.dart
      theme.dart
    features/
      login/
      dashboard/
      role_menu/
      travel_groups/
      sales_orders/
      order_qrcodes/
      taster_summary/
      finance/
      warehouse/
      after_sales/
      analytics/
      ai_assistant/
      shell/
    shared/
      widgets/
```

设计原则：

- 先保证内部员工高频录入和查询路径清楚。
- Windows 端使用左侧导航和宽屏双栏布局。
- 手机端使用抽屉导航和单列表单布局。
- 所有页面先接假数据，后续按模块接后端接口。

## 3. 共享常量包

`packages/shared` 当前提供 Dart 常量和格式化能力：

- 用户角色：管理员、老板、前台、销售、财务、库管、售后、品鉴师。
- 角色菜单入口：按角色限制可见页面。
- 订单状态、配送方式、打包状态、售后状态。
- 物流方式、团型、日期预设。
- 金额格式化：输入单位为分，展示为元。
- 日期格式化。

后端当前已经迁移到 NestJS + Prisma。后续如需进一步避免前后端口径分裂，可考虑从同一份枚举源生成 Dart 和 TypeScript 常量。

## 6. 适配方式

手机端：

- 页面主体为单列。
- 导航放在抽屉里。
- 表单字段自动按一列排列。
- 查询条件使用换行的筛选标签，避免横向溢出。

Windows 端：

- 左侧固定导航，右侧内容区。
- 录入页和查询页优先双栏：左侧列表/表单，右侧核对/维护区。
- 指标卡片按宽度自动从 1 列扩展到 2 列或 4 列。

## 7. 本地运行

后端启动后，在 Flutter 目录运行：

```powershell
cd D:\jiangjiu\apps\mobile_desktop
flutter pub get
flutter run -d windows --dart-define=JIANGJIU_API_BASE_URL=http://127.0.0.1:3000
```

当前仓库已包含 Windows 平台目录。需要 Android/iOS 时可生成：

```powershell
cd D:\jiangjiu\apps\mobile_desktop
flutter create . --platforms=android,ios
```

## 8. 当前限制

- 页面使用假数据，不会写入后端。
- 当前只真实接入登录和 `/api/auth/me` 会话恢复。
- 二维码为占位图案，真实二维码生成留到第 5 阶段。
- 数据分析和 AI 助手只保留 UI 路径，真实统计和大模型查询留到第 8、9 阶段。
