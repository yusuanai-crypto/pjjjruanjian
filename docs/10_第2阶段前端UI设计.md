# 第 2 阶段前端 UI 设计

## 1. 本次实现范围

本阶段已经从纯 UI 骨架推进到部分真实业务接口接入。登录、会话恢复、后端返回菜单、全局标记查询开关、旅行团录入和标记、待处理旅行团列表、订单录入保存、订单管理列表和标记、旅行团离店备注、财务概览、对账表读写已经调用后端接口。

仍有一批页面保持 UI 骨架或局部假数据，主要用于保留业务入口和交互路径：旅行团查询、积分表、二维码销售单、品鉴师总结、库管打包、售后开单、数据分析、AI 助手等还没有完整业务保存或真实查询。

新增目录：

```text
apps/mobile_desktop/
packages/shared/
```

设计原则：

- 先保证内部员工高频录入和查询路径清楚。
- Windows 端使用左侧导航和宽屏双栏布局。
- 手机端使用抽屉导航和单列表单布局。
- 页面状态按“已接真实后端、部分接入、仍为假数据”分层维护，避免把 UI 骨架误认为完整业务能力。

## 3. 共享常量包

`packages/shared` 当前提供 Dart 常量和格式化能力：

- 用户角色：管理员、老板、前台、销售、财务、库管、售后、品鉴师。
- 角色菜单入口：按角色限制可见页面。
- 订单状态、配送方式、打包状态、售后状态。
- 物流方式、团型、日期预设。
- 金额格式化：输入单位为分，展示为元。
- 日期格式化。

后端当前已经迁移到 NestJS + Prisma。后续如需进一步避免前后端口径分裂，可考虑从同一份枚举源生成 Dart 和 TypeScript 常量。

## 6. 适配方式

手机端：

- 页面主体为单列。
- 导航放在抽屉里。
- 表单字段自动按一列排列。
- 查询条件使用换行的筛选标签，避免横向溢出。

Windows 端：

- 左侧固定导航，右侧内容区。
- 录入页和查询页优先双栏：左侧列表/表单，右侧核对/维护区。
- 指标卡片按宽度自动从 1 列扩展到 2 列或 4 列。

## 7. 本地运行

后端启动后，在 Flutter 目录运行：

```powershell
cd D:\jiangjiu\apps\mobile_desktop
flutter pub get
flutter run -d windows --dart-define=JIANGJIU_API_BASE_URL=http://127.0.0.1:3000
```

当前仓库已包含 Windows 平台目录。需要 Android/iOS 时可生成：

```powershell
cd D:\jiangjiu\apps\mobile_desktop
flutter create . --platforms=android,ios
```

## 8. 当前限制

- 已接后端的页面仍不是完整业务闭环，例如订单录入的历史客户和酒品明细仍是页面内数据，旅行团离店页的订单勾选绑定还没有持久化。
- 旅行团、待处理旅行团、订单、财务概览、对账表已经有真实接口入口，但独立客户库、商品库、售后、库管、提成、统计分析和 AI 查询仍待后续阶段补齐。
- 二维码销售单仍为占位预览，真实二维码生成留到后续阶段。
- Android/iOS 平台目录未提交，需要移动端调试时按本文件命令生成。
