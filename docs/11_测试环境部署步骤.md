# 测试环境部署步骤：server/api

本文用于把 `server/api` 部署到云服务器测试环境，连接 MySQL，执行 Prisma `migrate deploy` 和 seed，然后启动 NestJS API。

注意：本文不记录任何真实密码、密钥或完整生产连接串。所有 `<...>` 都需要从密码管理器或云控制台获取后在服务器上填写。

## 0. 当前代码部署前确认

根据当前仓库状态，部署前必须先确认下面几项：

- Prisma 使用 MySQL，连接串来自 `DATABASE_URL`：`server/api/prisma/schema.prisma`。
- seed 文件是 `server/api/prisma/seed.ts`，会读取 `SEED_ADMIN_PASSWORD` 和 `SEED_DEMO_PASSWORD`。
- `.env.example` 已列出需要的环境变量：`DATABASE_URL`、`AUTH_TOKEN_SECRET`、`AUTH_TOKEN_EXPIRES_IN_SECONDS`、`PRISMA_CONNECT_ON_BOOT`、`SEED_ADMIN_PASSWORD`、`SEED_DEMO_PASSWORD`。
- 当前 `server/api/package.json` 只有 `start` 和 `test`，没有 `build`、`prisma:generate`、`prisma:migrate:deploy`、`prisma:seed` 脚本。
- 当前仓库里的 `src/main.js` 是旧的原生 Node HTTP 入口，只覆盖准备确认模块，不是完整 NestJS API。
- 本机存在的 `server/api/dist` 和 `server/api/node_modules` 已被 `.gitignore` 忽略，不能假设云服务器从 Git 拉代码后会有这些文件。

因此，正式执行本部署步骤前，需要先保证仓库或发布包中已经包含完整 NestJS 源码、依赖声明、构建配置，并能生成 `dist/main.js`。如果当前仓库仍保持上述状态，部署到云服务器后只能启动旧入口：

```bash
node -r dotenv/config src/main.js
```

这不满足“启动 NestJS API”的目标。

建议在部署前补齐并提交类似脚本，或在 CI 产物中提供等价命令：

```json
{
  "scripts": {
    "build": "nest build",
    "start": "node -r dotenv/config dist/main.js",
    "prisma:generate": "prisma generate",
    "prisma:migrate:deploy": "prisma migrate deploy",
    "prisma:seed": "ts-node --transpile-only prisma/seed.ts",
    "test": "node --test test/*.test.js"
  },
  "prisma": {
    "seed": "ts-node --transpile-only prisma/seed.ts"
  }
}
```

## 1. 约定变量

后续命令默认在 Ubuntu 云服务器执行。

```bash
export APP_DIR="/opt/jiangjiu"
export API_DIR="$APP_DIR/server/api"
export DEPLOY_REF="<BRANCH_TAG_OR_COMMIT>"
export GIT_REPO="<GIT_SSH_OR_HTTPS_REPO_URL>"
export API_DOMAIN="<API_DOMAIN_OR_SERVER_IP>"
```

## 2. 安装服务器基础依赖

```bash
sudo apt update
sudo apt install -y git curl build-essential nginx netcat-openbsd
node -v
npm -v
pm2 -v || sudo npm install -g pm2
```

建议 Node.js 使用当前测试环境已验证的大版本，至少保证与本地构建环境一致。

## 3. 拉取或更新代码

首次部署：

```bash
sudo mkdir -p "$APP_DIR"
sudo chown -R "$USER:$USER" "$APP_DIR"
git clone "$GIT_REPO" "$APP_DIR"
cd "$APP_DIR"
git checkout "$DEPLOY_REF"
git rev-parse --short HEAD
```

后续更新：

```bash
cd "$APP_DIR"
git fetch --all --tags
git checkout "$DEPLOY_REF"
git pull --ff-only
git rev-parse --short HEAD
```

## 4. 创建环境变量文件

在服务器上创建 `server/api/.env`。不要把真实 `.env` 提交到 Git。

```bash
cd "$API_DIR"
umask 077
cat > .env <<'EOF'
DATABASE_URL="mysql://<DB_USER>:<URL_ENCODED_DB_PASSWORD>@<MYSQL_INTERNAL_HOST>:3306/<DB_NAME>"
AUTH_TOKEN_SECRET="<RANDOM_SECRET_FROM_PASSWORD_MANAGER>"
AUTH_TOKEN_EXPIRES_IN_SECONDS="86400"
PRISMA_CONNECT_ON_BOOT="true"
RATE_LIMIT_STORE="database"
RATE_LIMIT_KEY_SECRET="<RANDOM_FINGERPRINT_SECRET_FROM_PASSWORD_MANAGER>"
LOGIN_RATE_LIMIT_MAX_REQUESTS="5"
LOGIN_RATE_LIMIT_WINDOW_SECONDS="900"
SMS_CODE_RATE_LIMIT_MAX_REQUESTS="3"
SMS_CODE_RATE_LIMIT_WINDOW_SECONDS="3600"
SMS_VERIFICATION_DEBUG="false"
PASSWORD_RESET_RATE_LIMIT_MAX_REQUESTS="5"
PASSWORD_RESET_RATE_LIMIT_WINDOW_SECONDS="900"
AI_RATE_LIMIT_MAX_REQUESTS="10"
AI_RATE_LIMIT_WINDOW_SECONDS="60"
AI_DAILY_LIMIT_PER_USER="100"
TRUSTED_PROXY_IPS="<EXACT_DIRECT_PROXY_IPS_OR_EMPTY>"
SEED_ADMIN_PASSWORD="<INITIAL_ADMIN_PASSWORD_FROM_PASSWORD_MANAGER>"
SEED_CREATE_DEMO_USERS="false"
SEED_DEMO_PASSWORD="<INITIAL_DEMO_PASSWORD_FROM_PASSWORD_MANAGER>"
PORT="3000"
EOF
chmod 600 .env
```

检查 `.env` 是否包含必要键名，命令只输出布尔值，不打印敏感内容：

```bash
cd "$API_DIR"
node -e "const fs=require('fs'); const text=fs.readFileSync('.env','utf8'); console.log({DATABASE_URL:/^DATABASE_URL=/m.test(text), AUTH_TOKEN_SECRET:/^AUTH_TOKEN_SECRET=/m.test(text), PORT:/^PORT=/m.test(text)})"
```

预期至少看到：

```text
{ DATABASE_URL: true, AUTH_TOKEN_SECRET: true, PORT: true }
```

`DATABASE_URL` 中的数据库密码如果包含 `@`、`#`、`:`、`/`、空格等特殊字符，必须先 URL encode。

## 5. 验证 MySQL 连通性

```bash
nc -vz <MYSQL_INTERNAL_HOST> 3306
```

如果服务器安装了 MySQL 客户端，可以再验证账号权限。密码通过交互输入，不写在命令里：

```bash
mysql -h <MYSQL_INTERNAL_HOST> -P 3306 -u <DB_USER> -p -e "SELECT 1;"
```

测试库建议提前创建好，并使用 `utf8mb4`：

```bash
mysql -h <MYSQL_INTERNAL_HOST> -P 3306 -u <ADMIN_DB_USER> -p -e "CREATE DATABASE IF NOT EXISTS <DB_NAME> CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
```

## 6. 安装依赖并构建

```bash
cd "$API_DIR"
if [ -f package-lock.json ]; then
  npm ci
else
  npm install
fi
```

执行部署前检查。下面命令失败时，先修复代码或发布包，不要继续迁移数据库：

```bash
cd "$API_DIR"
node -e "const p=require('./package.json'); for (const s of ['build','start']) { if (!p.scripts || !p.scripts[s]) throw new Error('missing npm script: '+s); }"
test -f prisma/schema.prisma
test -f prisma/seed.ts
```

构建 NestJS API：

```bash
cd "$API_DIR"
npm run build
test -f dist/main.js
```

如果项目暂时没有 npm 脚本，但依赖已正确安装，也可以临时执行：

```bash
cd "$API_DIR"
npx nest build
test -f dist/main.js
```

## 7. 执行 Prisma generate、migrate deploy 和 seed

优先使用 npm 脚本：

```bash
cd "$API_DIR"
npm run prisma:generate
npm run prisma:migrate:deploy
npm run prisma:seed
```

如果脚本尚未补齐，使用当前代码可匹配的 `npx` 命令：

```bash
cd "$API_DIR"
npx prisma generate
npx prisma migrate deploy
npx ts-node --transpile-only prisma/seed.ts
```

查看迁移状态：

```bash
cd "$API_DIR"
npx prisma migrate status
```

seed 执行后，默认管理员和演示账号的初始密码来自 `.env`，首次登录后应立刻修改管理员密码。

## 8. 使用 PM2 启动 NestJS API

```bash
cd "$API_DIR"
pm2 delete jiangjiu-api || true
pm2 start node --name jiangjiu-api -- -r dotenv/config dist/main.js
pm2 status
```

保存 PM2 进程列表，并按 `pm2 startup` 输出的命令配置开机自启：

```bash
pm2 save
pm2 startup
```

本机验证：

```bash
curl -i http://127.0.0.1:3000/api/auth/me
```

预期返回 `401`，并带有类似 `AUTH_TOKEN_REQUIRED` 的错误码，说明服务、路由和鉴权链路已启动。

## 9. 配置 Nginx 反向代理

测试环境可先使用 HTTP，将公网 `80` 转发到本机 `3000`。

```bash
sudo tee /etc/nginx/sites-available/jiangjiu-api >/dev/null <<'EOF'
server {
    listen 80;
    listen [::]:80;

    server_name <API_DOMAIN_OR_SERVER_IP>;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF

sudo ln -sfn /etc/nginx/sites-available/jiangjiu-api /etc/nginx/sites-enabled/jiangjiu-api
sudo nginx -t
sudo systemctl reload nginx
```

公网验证：

```bash
curl -i http://<API_DOMAIN_OR_SERVER_IP>/api/auth/me
```

预期同样返回 `401 AUTH_TOKEN_REQUIRED` 一类响应。

## 11. 回滚方法

### 11.1 仅回滚 API 代码

适用于代码启动失败、接口异常，但数据库迁移已确认不需要回退的情况。

```bash
cd "$APP_DIR"
git fetch --all --tags
git checkout <PREVIOUS_GOOD_COMMIT_OR_TAG>

cd "$API_DIR"
if [ -f package-lock.json ]; then
  npm ci
else
  npm install
fi
npx prisma generate
npm run build
pm2 restart jiangjiu-api --update-env
pm2 status
curl -i http://127.0.0.1:3000/api/auth/me
```

### 11.2 回滚数据库

Prisma migration 默认没有自动 down 脚本。测试环境最稳妥的回滚方式是迁移前先做数据库备份，需要回滚时恢复备份。

迁移前备份：

```bash
mkdir -p /opt/backups
BACKUP_TIME="$(date +%Y%m%d%H%M%S)"
mysqldump --single-transaction --routines --triggers \
  -h <MYSQL_INTERNAL_HOST> -P 3306 -u <DB_USER> -p <DB_NAME> \
  > "/opt/backups/jiangjiu-${BACKUP_TIME}.sql"
```

测试环境确认可以清库恢复时执行：

```bash
pm2 stop jiangjiu-api

mysql -h <MYSQL_INTERNAL_HOST> -P 3306 -u <ADMIN_DB_USER> -p -e "DROP DATABASE IF EXISTS <DB_NAME>; CREATE DATABASE <DB_NAME> CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
mysql -h <MYSQL_INTERNAL_HOST> -P 3306 -u <DB_USER> -p <DB_NAME> < /opt/backups/<BACKUP_FILE>.sql

cd "$API_DIR"
npx prisma migrate status
pm2 restart jiangjiu-api --update-env || pm2 start node --name jiangjiu-api -- -r dotenv/config dist/main.js
```

如果不允许覆盖原测试库，可以恢复到新库，再修改 `.env` 的 `DATABASE_URL` 指向新库：

```bash
mysql -h <MYSQL_INTERNAL_HOST> -P 3306 -u <ADMIN_DB_USER> -p -e "CREATE DATABASE <DB_NAME_ROLLBACK> CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
mysql -h <MYSQL_INTERNAL_HOST> -P 3306 -u <DB_USER> -p <DB_NAME_ROLLBACK> < /opt/backups/<BACKUP_FILE>.sql

cd "$API_DIR"
cp .env ".env.$(date +%Y%m%d%H%M%S).bak"
export OLD_DB_NAME="<DB_NAME>"
export ROLLBACK_DB_NAME="<DB_NAME_ROLLBACK>"
sed -i "s#/${OLD_DB_NAME}\"#/${ROLLBACK_DB_NAME}\"#" .env
pm2 restart jiangjiu-api --update-env
```

### 11.3 迁移失败后的处理原则

先查看状态和失败原因：

```bash
cd "$API_DIR"
npx prisma migrate status
mysql -h <MYSQL_INTERNAL_HOST> -P 3306 -u <DB_USER> -p <DB_NAME> -e "SELECT migration_name, finished_at, rolled_back_at, logs FROM _prisma_migrations ORDER BY started_at DESC LIMIT 5;"
```

如果 migration 已部分执行，优先恢复备份。只有在已经人工确认数据库结构和迁移记录一致时，才使用 Prisma resolve：

```bash
npx prisma migrate resolve --rolled-back <FAILED_MIGRATION_NAME>
```

不要在不了解实际表结构的情况下直接标记迁移成功。

## 12. 常见排错

### npm 安装失败

```bash
cd "$API_DIR"
node -v
npm -v
ls -la package.json package-lock.json
npm install
```

如果仓库没有 `package-lock.json`，`npm ci` 会失败；测试环境可暂用 `npm install`，后续建议提交锁文件保证依赖版本稳定。

### 缺少 build 或 Prisma 脚本

```bash
cd "$API_DIR"
node -e "console.log(require('./package.json').scripts)"
```

当前仓库如果仍只有 `start`、`test`，说明部署脚本未补齐。先补齐 `package.json` 和依赖，再部署。

### Prisma 连不上 MySQL

常见错误：`P1001`。

```bash
nc -vz <MYSQL_INTERNAL_HOST> 3306
node -r dotenv/config -e "const u=new URL(process.env.DATABASE_URL); console.log(u.hostname, u.port, u.pathname)"
```

检查项：

- RDS 白名单是否放行 ECS 内网 IP。
- ECS 与 RDS 是否在同一 VPC 或网络可达。
- `DATABASE_URL` 里的主机、端口、库名是否正确。

### Prisma 账号密码错误

常见错误：`P1000`。

处理方法：

- 在 MySQL 控制台重置数据库用户密码。
- 确认 `.env` 里的密码已 URL encode。
- 使用 `mysql -u <DB_USER> -p` 手工验证。

### seed 执行失败

```bash
cd "$API_DIR"
npx ts-node --transpile-only prisma/seed.ts
```

当前 seed 会引用认证模块里的密码哈希工具。如果报 `Cannot find module '../src/modules/auth/password'`，说明完整 NestJS 源码没有进入仓库或发布包，需要先补齐源码再执行 seed。

如果报唯一键冲突或重复数据，先确认 seed 是否使用 `upsert`，再查看具体表：

```bash
mysql -h <MYSQL_INTERNAL_HOST> -P 3306 -u <DB_USER> -p <DB_NAME> -e "SELECT username, role, is_active FROM users;"
```

### API 启动后 502

```bash
pm2 status
pm2 logs jiangjiu-api --lines 100
sudo nginx -t
sudo tail -n 100 /var/log/nginx/error.log
curl -i http://127.0.0.1:3000/api/auth/me
```

如果本机 `3000` 不通，先修 API；如果本机通而公网不通，查 Nginx、云安全组和 UFW。

### 端口被占用

```bash
sudo ss -ltnp | grep ':3000'
pm2 list
pm2 delete jiangjiu-api || true
```

确认没有旧进程后重新启动：

```bash
cd "$API_DIR"
pm2 start node --name jiangjiu-api -- -r dotenv/config dist/main.js
```

### 环境变量没有生效

```bash
cd "$API_DIR"
node -r dotenv/config -e "console.log(Boolean(process.env.DATABASE_URL), Boolean(process.env.AUTH_TOKEN_SECRET), process.env.PORT)"
pm2 restart jiangjiu-api --update-env
pm2 logs jiangjiu-api --lines 50
```

如果修改了 `.env`，PM2 需要 `--update-env` 才能让新环境变量进入进程。
