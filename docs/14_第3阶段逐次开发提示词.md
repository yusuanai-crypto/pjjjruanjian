# 第 3 阶段逐次开发提示词

本文根据 `docs/13_第3阶段旅行团管理开发文档.md` 的 26 步开发顺序生成。每次开发建议只复制一条提示词给 Codex，完成、验证、提交或确认后，再进入下一条。

通用要求：

- 每次开始前先阅读 `docs/13_第3阶段旅行团管理开发文档.md`。
- 只做当前提示词指定范围，不顺手做后续阶段。
- 不覆盖生产数据，不连接生产库。
- 如涉及测试环境，只使用云服务器测试 API 和测试库。
- 如遇到现有未提交改动，先说明，不要擅自回滚用户改动。
- 每次完成后说明改了哪些文件、跑了哪些测试、还有哪些风险。

## 15. 开发待处理自动计算

```text
请开发待处理旅行团自动计算逻辑，并接入 GET /api/pending-travel-groups。

规则：
1. 缺少品鉴师 -> pending_front_desk。
2. 缺少导游姓名、导游手机号、旅行社或人数 -> pending_front_desk。
3. 无订单且品鉴师总结未填写 -> pending_taster。
4. 财务未标记且超过当天结束时间 -> pending_finance。
5. 数据异常，如人数为 0、团号重复、离店早于进店 -> abnormal。

明确排除：
- 缺少离店时间不进入待处理。
- 已有订单但旅行团未补离店备注不进入待处理。

返回：
- pendingStatus
- pendingReasons

验证：
- 每条规则都有测试。
- 多原因时返回原因数组。
- 角色数据范围仍生效。
- npm test。
```
