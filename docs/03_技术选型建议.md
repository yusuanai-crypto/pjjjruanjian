# 技术选型建议

本文用尽量简单的话说明：这个项目应该用什么技术、为什么这么选、第一版不要做哪些复杂事情。

## 1. 结论

推荐技术方案：

- 客户端：Flutter
- 后端服务：Node.js + NestJS
- 数据库：MySQL
- 数据库操作：Prisma
- 部署：Docker + 云服务器
- 反向代理和 HTTPS：Nginx
- AI 能力：通过后端调用大模型 API

整体结构：

```text
安卓 App / 苹果 App / Windows 软件
              |
              | 通过 HTTPS 请求数据
              |
云服务器上的后端 API
              |
              | 读写数据
              |
MySQL 数据库
```

为什么这样设计：员工虽然不用网页，但多人必须共享同一份数据，所以一定需要服务器和数据库。App 负责界面和操作，服务器负责数据、权限、统计和 AI。

## 2. 客户端选择 Flutter

Flutter 可以用一套代码开发：

- 安卓 App
- 苹果 App
- Windows 桌面软件

为什么推荐 Flutter：

- 适合跨平台，一套代码覆盖三类设备。
- 界面表现稳定，适合做表单、列表、统计看板。
- Windows 桌面支持比较成熟，适合公司电脑使用。
- 后期如果要做扫码、二维码生成、拍照留存、文件导出，也有较多插件可用。

为什么不推荐一开始做三个原生 App：

- 安卓、苹果、Windows 各写一套，成本高。
- 每个功能要开发三遍。
- 小团队维护压力很大。

为什么不按纯网页来做：

- 用户明确需要安卓、苹果和 Windows 软件。
- App 可以提供更接近内部办公软件的体验。
- Windows 文件保存、安装分发和大屏录入更符合员工习惯。

## 3. 后端选择 Node.js + NestJS

后端负责：

- 登录
- 权限
- 全局标记查询控制
- 二维码销售单生成和校验
- 旅行团数据
- 订单数据
- 售后数据
- 提成积分
- 数据分析
- AI 查询
- 操作日志

为什么推荐 NestJS：

- 结构清晰，适合业务系统。
- 容易按模块拆分，例如订单模块、旅行团模块、售后模块。
- TypeScript 能减少很多低级错误。
- 和 Prisma、MySQL 配合很好。

为什么后端不能省：

如果每台手机或电脑都自己保存数据，就无法保证数据一致。财务、老板、售后看到的数据可能不一样。后端统一管理数据，是多人协作系统的基础。

## 4. 数据库选择 MySQL

数据库负责长期保存：

- 员工账号
- 旅行团
- 客户
- 订单
- 售后
- 提成
- 积分
- 操作日志

为什么推荐 MySQL：

- 稳定可靠，适合正式业务系统。
- 部署和运维资料多，很多云服务器和面板都默认支持。
- 和 Prisma 配合成熟，适合用 schema 管理表结构。
- 支持复杂条件筛选，适合老板看报表。
- 后期数据量变大也能继续使用。

为什么不直接用 Excel：

Excel 适合导出和临时核对，不适合作为多人同时使用的数据库。多人同时改 Excel 很容易冲突，也难做权限和日志。

## 5. 数据库操作选择 Prisma

Prisma 是后端代码和数据库之间的工具。

为什么需要它：

- 让开发者用更清晰的方式读写数据库。
- 数据表结构可以用代码管理。
- 后期改字段、加表更容易追踪。
- 对编程小白来说，文档和代码结构更容易理解。

Prisma schema 文件放在 `server/api/prisma/schema.prisma`，第一版按 MySQL 编写。后端连接数据库时，`DATABASE_URL` 使用类似 `mysql://用户名:密码@服务器地址:3306/jiangjiu` 的格式。

## 6. 部署选择 Docker + 云服务器

第一版推荐部署到云服务器。

服务器上运行：

- 后端 API
- MySQL 数据库
- Nginx
- 定时备份任务

为什么用云服务器：

- 安卓、苹果、Windows 都能随时访问。
- 老板不在公司也可以看数据。
- 员工换设备后重新登录即可。
- 数据集中备份更可靠。

为什么用 Docker：

- 部署更标准。
- 后端、数据库、Nginx 可以统一管理。
- 换服务器时更容易迁移。

## 7. AI 能力设计

AI 不直接连接数据库。

正确流程：

```text
用户在 App 输入问题
        |
后端检查用户身份和权限
        |
后端查询允许访问的数据
        |
后端把结果交给 AI 总结
        |
App 显示 AI 回答
```

为什么要这样做：

- 避免 AI 看到不该看的数据。
- 避免 AI 直接改错数据。
- 所有查询仍然经过系统权限控制。
- 如果老板或前台开启“只查询已标记信息”，后端必须在所有普通查询、统计和 AI 查询前统一加上标记过滤，不能只靠 App 前端隐藏；恢复该开关必须走管理员权限。

第一版 AI 能做：

- 查询销售额
- 查询退单
- 查询客户订单
- 查询品鉴师排名
- 解释经营指标
- 给出经营建议

第一版 AI 不做：

- 直接修改订单
- 直接删除数据
- 绕过权限查询全部数据

## 8. 安装和分发方式

### 安卓

第一版可以通过 APK 内部分发。

为什么：不上应用市场也能先在公司内部安装测试，上线速度快。

### 苹果

第一版通过 TestFlight 内测。

为什么：适合内部员工试用，比正式上架 App Store 更快，但需要苹果开发者账号。

### Windows

第一版生成 Windows 安装包。

为什么：员工电脑安装后像普通办公软件一样使用，适合批量录入、查询和导出文件。

## 9. 第一版不建议做的复杂技术

### 不做复杂离线同步

原因：

- 离线录入后再同步，可能出现同一订单被多人修改。
- 冲突处理很复杂。
- 第一版联网使用更稳妥。

可保留简单能力：

- 网络断开时提示无法保存。
- 已打开的数据可以临时查看。
- 提交失败时保留输入内容，方便重新提交。

### 不做微服务

原因：

- 当前是单公司内部系统，不需要一开始拆很多服务。
- 微服务会增加部署、排查和维护成本。

第一版一个后端 API 服务即可。

### 不做完整库存系统

原因：

- 库存系统本身是一个大项目。
- 当前最急的是订单、发货和查询。

第一版库管先围绕订单和物流使用。

## 10. 推荐开发环境

开发者电脑需要：

- Flutter SDK
- Node.js
- MySQL 或 Docker
- VS Code
- Git

为什么这样配置：

- Flutter 开发 App。
- Node.js 开发后端。
- MySQL 存业务数据。
- Docker 模拟正式服务器环境。
- Git 保存每一步代码变化，方便回退和协作。

## 11. 推荐上线环境

云服务器建议：

- 2 核 CPU
- 4GB 内存
- 80GB 以上硬盘
- Ubuntu Linux
- 域名和 HTTPS 证书
- 每日数据库备份

为什么这样配置：

第一版用户量是公司内部员工，不需要特别高配置。重点是稳定、备份、安全，而不是一开始买很贵的服务器。
