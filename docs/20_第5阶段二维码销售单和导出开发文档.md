# 第 5 阶段二维码销售单和导出开发文档

版本：v0.1
状态：根据 `docs/06_开发阶段计划.md` 第 5 阶段目标整理。进入开发前先确认第 4 阶段客户、订单、旅行团关联、本地测试和测试库 smoke 已稳定。

## 1. 阶段目标

第 5 阶段目标是把“二维码销售单”和“Excel 导出”做成真实可用闭环：

- 销售可以从订单详情或二维码销售单页面生成二维码。
- 二维码指向该订单的公开销售单详情页，客人手机扫码即可查看。
- 客人可以对手机页面或销售手机/电脑上的二维码销售单拍照留存。
- 财务和管理员可以按当前筛选条件导出销售订单 Excel。
- 财务和管理员可以按当前筛选条件导出旅行团 Excel。
- 导出字段和页面显示口径一致，并遵守角色权限和全局“只查询已标记信息”开关。

本阶段完成后，里程碑 2“能录订单和生成二维码”才算真正闭环。

## 2. 本阶段不做的事

- 不做打印销售单。
- 不做完整售后单流程。
- 不做提成、积分、扣酒成本计算或提成导出。
- 不做 AI 查询。
- 不做复杂文件管理中心。
- 不把二维码公开页做成需要客户登录的系统。
- 不连接生产库，不覆盖生产数据。

## 4. 业务规则

### 4.1 二维码销售单规则

- 二维码内容是公开销售单 URL，不直接把订单内容编码进二维码。
- 默认 URL：`{PUBLIC_SALES_SHEET_BASE_URL}/api/public/sales-sheets/{token}`。
- 如果未配置 `PUBLIC_SALES_SHEET_BASE_URL`，可用请求 host 生成，但测试和生产环境建议显式配置。
- token 必须随机、不可猜，建议使用 Node `crypto.randomBytes(24).toString('base64url')` 或等价方案。
- 一个订单默认复用已有未过期 token；只有用户明确重新生成时才替换 token。
- `qrCodeExpiresAt` 可为空。为空表示长期有效，适合“拍照留存”业务。
- 如果设置有效期，公开页过期后只显示“二维码已过期，请联系销售”，不展示订单内容。
- 订单被取消或已退单后，公开页是否继续展示由业务确认；默认仍展示订单状态，避免客户留存信息突然打不开。

### 4.2 公开销售单展示规则

公开页面不需要登录，但必须只通过 token 访问。

建议展示：

- 公司名称：贵州酱酒馆。
- 系统单号 `orderNo`。
- 销售单号 `salesFormNo`，为空则不显示。
- 下单日期。
- 客户姓名。
- 客户电话默认脱敏，例如 `138****0000`。
- 收货地址：默认显示完整地址，便于客户核对；如业务担心隐私，可改成部分脱敏。
- 旅行团概要：团号、旅行社、导游或品鉴师，按已有 DTO 能提供的字段展示。
- 销售人员姓名。
- 酒品明细：品名、数量、单价、小计、配送选择。
- 订单总额。
- 货到付款金额。
- 订单状态。
- 物流方式、物流单号：如已有则显示。
- 开票状态：如已有则显示。
- 备注：只显示适合客户看的订单备注，不显示内部财务备注、库管备注。

不展示：

- 客户财务标记、订单财务标记。
- 财务备注、库管备注。
- 运费成本、扣酒成本、提成、积分。
- 操作日志。
- 内部用户 ID。

### 4.3 角色权限

二维码生成：

| 角色 | 权限 |
| --- | --- |
| 管理员 | 可为任意可见订单生成、重新生成二维码 |
| 销售 | 可为自己负责或自己可见订单生成二维码 |
| 财务 | 可查看二维码信息，是否允许重新生成按业务决定；默认允许查看，不主动生成 |
| 售后 | 可查看销售单详情，不生成 |
| 老板 | 可查看，不生成 |
| 库管 | 默认不生成 |
| 前台、品鉴师 | 默认不进入二维码销售单 |

Excel 导出：

| 角色 | 权限 |
| --- | --- |
| 管理员 | 可导出销售订单和旅行团 |
| 财务 | 可导出销售订单和旅行团 |
| 老板 | 可选只读导出；如果文档口径保持“财务和管理员导出”，则不开放 |
| 其他角色 | 默认不可导出 |

建议第 5 阶段先严格按 PRD：管理员和财务可导出。

### 4.4 全局标记过滤

当 `only_show_marked_records=true`：

- 销售订单导出必须使用和 `/api/sales-orders` 一致的查询范围。
- 订单必须满足客户 `financeMark=true`。
- 如果订单关联旅行团，还必须旅行团 `financeMark=true`。
- 旅行团导出必须使用和 `/api/travel-groups` 一致的查询范围。
- 二维码生成的鉴权查询也应遵守当前角色数据范围；公开页已持有 token，不再按当前登录用户过滤。

qrCodeGeneratedAt DateTime? @map("qr_code_generated_at") @db.DateTime(0)

```

```

兼容要求：

## 6. 后端 API 设计

### 6.1 认证销售单预览

```text
GET /api/sales-orders/:id/sales-sheet
```

用途：

- Flutter 二维码销售单页面加载订单销售单信息。
- 订单详情页生成二维码前后展示同一份 DTO。

返回建议：

```json
{
  "salesSheet": {
    "order": {},
    "items": [],
    "travelGroup": {},
    "qrCode": {
      "token": "optional-token",
      "url": "optional-url",
      "generatedAt": "2026-07-01T10:00:00.000Z",
      "expiresAt": null
    }
  }
}
```

权限：

- 沿用 `getSalesOrder` 的读取范围。

### 6.2 生成二维码

```text
POST /api/sales-orders/:id/qr-code
```

请求体：

```json
{
  "expiresInDays": null,
  "regenerate": false
}
```

规则：

- `expiresInDays=null` 或缺省：不过期。
- `expiresInDays` 如传入，必须是 1 到 3650 的整数。
- `regenerate=false` 且已有未过期 token 时复用。
- `regenerate=true` 时替换 token 并写操作日志。
- 写入 `qrCodeToken`、`qrCodeGeneratedAt`、`qrCodeExpiresAt`。

返回：

```json
{
  "salesSheet": {},
  "qrCode": {
    "token": "...",
    "url": "https://example.com/api/public/sales-sheets/...",
    "expiresAt": null
  }
}
```

### 6.3 公开扫码页

```text
GET /api/public/sales-sheets/:token
```

实现建议：

- 直接返回移动端友好的 HTML。
- 由于全局 `ApiResponseInterceptor` 会包 JSON，建议在 controller 中使用 `@Res()` 直接 `response.type('html').send(html)`。
- HTML 使用后端字符串模板即可，不引入前端构建。
- 所有动态文本必须 HTML escape。
- 不返回内部字段。
- token 不存在、过期、订单不存在时返回友好 HTML，HTTP 状态可用 404 或 410。

### 6.4 销售订单 Excel 导出

```text
GET /api/sales-orders/export.xlsx
```

查询参数：

- 复用 `/api/sales-orders`：`dateFrom`、`dateTo`、`query`、`customerId`、`customerPhone`、`travelGroupId`、`orderType`、`status`、`deliveryType`、`packingStatus`、`financeMark`、`customerFinanceMark`、`salesUserId`。

权限：

- `admin`、`finance`。

实现建议：

- 后端使用 `exceljs` 生成 `.xlsx`。
- controller 使用 `@Res()` 直接发送 buffer，避免被 JSON interceptor 包装。
- 文件名建议：`sales-orders-YYYYMMDD-HHmmss.xlsx`。
- 单次导出建议限制最大行数，例如 5000 行；超过返回明确错误，引导缩小筛选范围。

字段建议：

| Excel 列 | 来源 |
| --- | --- |
| 系统单号 | `orderNo` |
| 销售单号 | `salesFormNo` |
| 订单日期 | `orderDate` |
| 客户姓名 | `customerName` |
| 客户电话 | `customerPhone` |
| 地址 | `province + city + district + address` |
| 旅行团号 | `travelGroup.groupNo` |
| 旅行社 | `travelGroup.travelAgency` |
| 销售人员 | `salesUser.name` 或 DTO 中已有销售名称 |
| 酒品明细 | 多明细合并，例如 `品名 x 数量` |
| 配送摘要 | `deliverySummary` |
| 订单总额 | 元，保留两位 |
| 货到付款金额 | 元，保留两位 |
| 订单状态 | 中文标签 |
| 客户标记 | 已标记/未标记 |
| 订单标记 | 已标记/未标记 |
| 打包状态 | 中文标签 |
| 物流方式 | `logisticsMethod` |
| 物流单号 | `logisticsNo` |
| 运费 | 元，保留两位 |
| 是否需要开票 | 是/否 |
| 是否已开票 | 是/否 |
| 创建时间 | `createdAt` |
| 更新时间 | `updatedAt` |

### 6.5 旅行团 Excel 导出

查询参数：

- `admin`、`finance`。

字段建议：

| Excel 列 | 来源 |
| --- | --- |
| 团号 | `groupNo` |
| 日期 | `visitDate` |
| 旅行社 | `travelAgency` |
| 车牌号 | `licensePlate` |
| 导游 | `guideName` |
| 导游电话 | `guidePhone` |
| 人数 | `guestCount` |
| 品鉴馆馆号 | `tastingRoomNo` |
| 品鉴师 | `tasterName` |
| 进店时间 | `arrivalTime` |
| 离店时间 | `departureTime` |
| 团型 | `groupType` |

| 品鉴师总结 | `tasterSummary` |
| 备注 | `remarks` |
| 创建时间 | `createdAt` |
| 更新时间 | `updatedAt` |

## 7. Flutter 客户端开发

### 7.1 依赖建议

建议新增：

```yaml
dependencies:
  qr_flutter: ^4.1.0
  path_provider: ^2.1.5
```

说明：

- `qr_flutter` 用于在 App 内渲染二维码。
- `path_provider` 用于把 Excel 文件保存到应用文档目录或下载目录附近。
- 如需要“保存销售单图片”，后续可再评估 `screenshot` 或平台保存能力；第 5 阶段验收以扫码和拍照留存为准。

### 7.2 ApiClient 二进制下载

`apps/mobile_desktop/lib/core/api/api_client.dart` 增加二进制 GET 能力：

- 支持 token。
- 返回 bytes、contentType、文件名。
- 非 2xx 时尽量解析 JSON 错误；解析失败则返回 HTTP 错误。

### 7.3 BusinessApi 方法

建议增加：

- `getSalesOrderSalesSheet(String id)`

## 9. 测试计划

### 9.1 后端测试

必须覆盖：

- `SalesOrder` 二维码字段 migration 和 Prisma generate。
- 生成 token 成功。
- 已有 token 未过期时复用。
- `regenerate=true` 时替换 token。
- 有效期参数非法时报错。
- 销售不能给别人的不可见订单生成二维码。
- 公开页 token 不存在返回友好错误。
- 公开页 token 过期返回友好错误。
- 公开页不展示内部字段。
- 公开页 HTML escape，避免客户姓名、备注等字段注入 HTML。
- 销售订单导出权限：admin/finance 成功，其他角色失败。
- 旅行团导出权限：admin/finance 成功，其他角色失败。
- 导出复用列表筛选和全局标记过滤。
- 导出字段包含页面核心字段。
- 写操作进入 `operation_logs`，至少覆盖二维码生成/重新生成。

### 9.2 Flutter 测试

必须覆盖：

- `SalesSheetRecord` JSON 解析。
- `ApiClient` 文件下载成功和错误处理。
- 二维码销售单页面加载、空状态、错误状态、生成成功状态。
- 订单详情中二维码按钮的角色可见性。

## 10. 验收标准

- 销售可以从订单生成真实二维码。
- 客人可以扫码打开公开销售单详情。

- 二维码链接不可猜，过期逻辑可用。
- 财务和管理员可以导出销售订单 Excel。
- 财务和管理员可以导出旅行团 Excel。
- Excel 字段和页面显示核心字段一致。
- 导出遵守角色权限、当前筛选条件和全局标记过滤。
