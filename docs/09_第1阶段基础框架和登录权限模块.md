# 第 1 阶段基础框架和登录权限模块

## 1. 当前完成范围

第 1 阶段当前已按 NestJS + MySQL + Prisma 路线落地，Flutter 客户端已能连接登录接口。当前主路径如下：

- 后端入口：`server/api/src/main.ts`
- Nest 模块：`server/api/src/app.module.ts`
- 全局接口前缀：`/api`
- 数据库 schema：`server/api/prisma/schema.prisma`
- 第 1 阶段迁移：`server/api/prisma/migrations/20260622000100_phase1_auth_settings_logs/migration.sql`
- seed：`server/api/prisma/seed.ts`
- Flutter 客户端：`apps/mobile_desktop`
- Flutter 共享包：`packages/shared`

已完成能力：

- 员工账号密码登录。
- Bearer token 鉴权。
- 登录后返回用户、角色权限、菜单和数据范围。
- App 启动时通过 `/api/auth/me` 恢复本地 token 会话。
- 管理员创建、查询、修改、停用、启用员工账号。
- 管理员重置员工密码，员工修改自己的密码。
- 老板、前台、管理员可开启全局“只查询已标记信息”开关。
- 只有管理员可恢复全局“只查询已标记信息”开关。
- 记录登录、账号管理、密码修改、全局开关和 seed 操作日志。

当前第 1 阶段只落库三类表：

- `users`
- `system_settings`
- `operation_logs`

第 0 阶段准备确认模块仍保留在 Nest 应用中，接口文档见 `docs/07_第0阶段准备确认模块.md`。第 2 阶段及后续业务模块尚未完成，范围见本文第 9 节。

## 2. 启动约定

默认管理员由 seed 创建：

| 字段 | 值 |
| --- | --- |
| 用户名 | `admin` |
| 初始密码 | 由 `SEED_ADMIN_PASSWORD` 从密钥管理系统注入，无默认值 |
| 用户 ID | `usr_admin` |
| 角色 | `admin` |

生产或真实测试环境应设置：

- `DATABASE_URL`：MySQL 连接串。
- `AUTH_TOKEN_SECRET`：token 签名密钥。
- `SEED_ADMIN_PASSWORD`：可选，用于覆盖默认 seed 管理员密码。
- `AUTH_TOKEN_EXPIRES_IN_SECONDS`：可选，默认 8 小时。

密码策略：

- 最短 8 个字符。
- 当前实现使用 Node.js `crypto.pbkdf2Sync` 生成 `pbkdf2_sha256` 哈希。

用户名规则：

- 3-50 个字符。
- 允许小写字母、数字、点、下划线、短横线。
- 后端会 trim 并转小写。

## 3. 统一响应格式

成功响应统一由 Nest 拦截器包成：

```json
{
  "data": {}
}
```

错误响应统一为：

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "错误说明"
  }
}
```

除登录接口外，受保护接口都需要请求头：

```http
Authorization: Bearer <token>
```

常见错误码：

| 错误码 | HTTP 状态 | 说明 |
| --- | --- | --- |
| `LOGIN_FIELDS_REQUIRED` | 400 | 登录缺少账号或密码 |
| `INVALID_CREDENTIALS` | 401 | 账号或密码错误 |
| `AUTH_TOKEN_REQUIRED` | 401 | 缺少 Bearer token |
| `INVALID_AUTH_TOKEN` | 401 | token 格式或签名无效 |
| `AUTH_TOKEN_EXPIRED` | 401 | token 已过期 |
| `ACCOUNT_DISABLED` | 403 | 账号已停用 |
| `ADMIN_REQUIRED` | 403 | 需要管理员权限 |
| `PERMISSION_DENIED` | 403 | 当前角色无权执行 |
| `WEAK_PASSWORD` | 400 | 密码不符合策略 |
| `USERNAME_EXISTS` | 409 | 用户名已存在 |
| `INVALID_ROLE` | 400 | 角色非法 |
| `USER_NOT_FOUND` | 404 | 员工不存在 |

## 4. 角色、权限和菜单

当前角色：

```text
admin, boss, front_desk, sales, finance, warehouse, after_sales, taster
```

第 1 阶段已经固定角色权限、菜单入口和数据范围返回结构，但部分菜单指向后续阶段页面或接口。例如 `travel_groups`、`sales_orders`、`commissions`、`analytics`、`ai_assistant` 只是后续阶段入口，业务 API 尚未实现。

### 5.6 管理员创建员工账号

`POST /api/users`

权限：`admin`。

成功状态码：`201`。

请求参数：

```json

  "name": "测试销售",
  "username": "sales01",
  "password": "Password123",
  "role": "sales",
  "phone": "13800000000",
  "leaderId": null,
```

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |

| `phone` | 否 | 手机号，可为空 |
| `leaderId` | 否 | 销售组长用户 ID，可为空 |
| `isActive` | 否 | 是否启用，默认 `true` |

## 6. 数据库迁移和 seed

本阶段迁移文件只创建登录权限所需表，不创建后续业务表：

```text
server/api/prisma/migrations/20260622000100_phase1_auth_settings_logs/migration.sql
```

本地开发首次启动：

```powershell
cd D:\jiangjiu\server\api
Copy-Item .env.example .env
npm.cmd install
npm.cmd run prisma:generate
npm.cmd run prisma:migrate:dev -- --name phase1_auth_settings_logs
npm.cmd run prisma:seed
npm.cmd run start:dev
```

已有迁移文件的环境，推荐直接执行：

```powershell
cd D:\jiangjiu\server\api
npm.cmd run prisma:migrate:deploy
npm.cmd run prisma:seed
```

seed 会执行：

- upsert 默认管理员 `admin`。
- upsert `only_show_marked_records=false`。
- upsert `marked_records_restore_required=false`。
- 写入一条 `seed.phase1` 操作日志。

旧 JSON 迁移到 MySQL 的脚本：

```powershell
cd D:\jiangjiu\server\api
npm.cmd run migrate:legacy-json -- --dry-run
npm.cmd run migrate:legacy-json -- --data-dir D:\backup\jiangjiu-data
```

脚本默认读取：

- `server/api/data/users.json`
- `server/api/data/system-settings.json`
- `server/api/data/operation-logs.json`

当前工作区没有这三个旧第 1 阶段 JSON 文件时，脚本会输出 `SKIP`，不视为失败。

- `users.json`、`system-settings.json`、`operation-logs.json`：如果从旧环境备份回来，只作为迁移来源；迁移后不要再作为运行期数据源。
- 不要手工编辑数据库表和旧 JSON 两份数据，避免账号、开关和日志状态分裂。
